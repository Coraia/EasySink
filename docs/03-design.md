# 开发文档

## 一、架构总览

### 三层标注 + 候选与过滤分离

```
                       原始英文文本
                            │
                            ▼
              ┌──────────────────────────┐
              │  Tokenizer（确定性）      │  分句 / 分词 / 全局 token 编号
              │  —— 全系统的坐标系 ——     │
              └────────────┬─────────────┘
                           │
            ┌──────────────┴──────────────┐
            ▼                             ▼
  ┌───────────────────┐        ┌────────────────────┐
  │ L0 词典层          │        │ L1 模型层           │
  │ 词汇              │        │ 习语/语法/文化      │
  │                   │        │                    │
  │ 零模型调用         │        │ 一篇一次调用        │
  │ 毫秒级 / 确定性    │        │ 产出**全量候选**     │
  │ 100% 可复现       │        │ **不看读者是谁**     │
  └─────────┬─────────┘        └──────────┬─────────┘
            │                             │
            │      标注候选池（带稀有度/领域标签）
            └──────────────┬──────────────┘
                           ▼
              ┌──────────────────────────┐
              │  L2 个性化过滤层           │
              │  读者模型在此唯一介入      │
              │  词频阈值 / 白黑名单 /     │
              │  领域标签 / 密度预算       │
              └────────────┬─────────────┘
                           ▼
                    最终标注列表
                （token 区间 + 中文注释）
```

### 为什么把"生成候选"和"按人过滤"分开

这是整个架构最重要的一个决定，带来三个直接收益：

1. **成本**：L1 结果与读者无关，可按文本哈希跨读者、跨会话缓存。同一篇文章第二次被任何人打开，模型调用成本为零。
2. **体验**：调节密度滑块时无需重新调用模型，纯本地过滤，**即时生效**。这是 PRD 决策 1 能成立的前提。
3. **可测试**：L1 的输出质量可以脱离读者模型独立评估，两层各自可回归。

### 铁律：能用词典解决的，绝不调模型

词汇层占全部标注量的 80% 以上，且完全可由词典确定性地解决。把词汇层交给模型是最常见的架构错误——成本高、有幻觉、不可复现、还慢。

模型只负责词典**结构上无法表达**的东西：跨词的习语、句子的结构、文本之外的文化背景。

## 二、已验证的技术事实

> 以下数据均为 2026-08-29 在本机实测所得，非文档抄录。实现时可直接依赖。

### 词库：ECDICT 1.0.28

| 项目 | 实测值 |
| --- | --- |
| 来源 | `https://github.com/skywind3000/ECDICT/releases/download/1.0.28/ecdict-sqlite-28.zip` |
| 压缩包 | 206 MB |
| 解压后 | **903 MB**（`stardict.db`，单表 `stardict`） |
| 词条总数 | **3,402,564** |
| COCA 词频（`frq`）有值 | 42,231 条，最大序号 47,062 |
| BNC 词频（`bnc`）有值 | 45,443 条，最大序号 50,000 |
| 至少一个语料库有值 | **56,992** 条 |
| 许可 | MIT |

**⚠ 最重要的推论：`词频 = 0` 不等于"生僻"。**

340 万词条里只有 5.7 万条有词频数据。剩下的 334 万条绝大多数是**专有名词、生物学名、罕见变形、词典噪音**。若把"无词频"当作"极生僻"来标注，结果是满屏噪音——这会直接违反 PRD 原则 1。

L0 必须对零词频词条采取保守策略（见第四节决策树）。

### 关键字段

| 字段 | 含义 | 实测说明 |
| --- | --- | --- |
| `frq` | COCA 词频序 | 越小越常见，0 = 无数据 |
| `bnc` | BNC 词频序 | 同上。与 COCA 互补，取两者较小值更稳 |
| `collins` | 柯林斯星级 1–5 | 5 星最常用。可作零词频时的兜底信号 |
| `oxford` | 是否牛津 3000 核心词 | 0/1 |
| `tag` | 考纲标签 | 实测取值：`zk gk cet4 cet6 ky ielts toefl gre` |
| `exchange` | 词形变换 | **`0:` 前缀直接给出原型** |
| `translation` | 中文释义 | 多行多义项，**带 `n.` `vt.` 词性前缀，需剥离** |

### 词形还原：两条路径实测对比

**路径 A — `exchange` 字段的 `0:` 码（推荐，与词条同源）**

```
running  →  exchange = "0:run/1:i/s:runnings"   →  原型 run
```

**路径 B — `lemma.en.txt`（外挂表，2.2 MB，作补充）**

```
格式：  be/4109826 -> is,was,are,were,'s,been,being,'re,'m,am,m
        ↑词  ↑语料频次      ↑全部变形，逗号分隔

原始行数 84,487，解析为反向映射后 101,909 条
```

**⚠ 已知缺陷：外挂表存在反向映射冲突。**

```
it/1213224 -> its,they
he/1196022 -> his,him,they      ← they 同时是 it 和 he 的变形
```

**解法**：词形还原前先查该词自身。若它自己就是词频序 ≤ 2000 的核心高频词，直接返回自身，不做还原。冲突只发生在功能词上，用词频短路即可完全绕开。

### 实测样例（用于实现后的回归比对）

| 输入 | 应还原为 | 词频序 | 期望行内注释 |
| --- | --- | --- | --- |
| `running` | running（自身有词频，不还原） | 3252 | 赛跑,流出,运转 |
| `ran` | run | 202 | 跑,赛跑,奔跑 |
| `mice` | mouse | 2845 | 老鼠,胆小羞怯的人,鼠标 |
| `better` | good | 452 | 较好的 |
| `they` | **they**（不可还原成 it） | 18 | — |
| `ubiquitous` | ubiquitous | 8148 | 无所不在的,到处存在的 |
| `photosynthesis` | photosynthesis | 17561 | 光合作用 |
| `serendipity` | serendipity | 23199 | 偶然发现珍宝的运气/才能 |
| `gerrymandering` | gerrymander | 35618 | 为本党利益改划选举区分 |
| `Obama` | obama | **0** | **不得标注**（专有名词） |

> 最后一行是 L0 正确性的关键测试用例。

### 为什么不用 spaCy / NLTK

1. 本机 Python 3.14，spaCy 的支持状况存疑，会拖慢启动
2. 模型文件数十 MB，增加部署体积与冷启动时间（未来上服务器直接变成成本）
3. **L0 只需要词形还原，不需要句法分析**。ECDICT 的 `exchange` + lemma 表已实测够用
4. 正则处理英文分词足够：`[A-Za-z]+(?:['’\-][A-Za-z]+)*` 可正确覆盖 `don't`、`state-of-the-art`、`O'Neill`

若 L1 未来需要真正的句法分析（例如自动识别倒装、非谓语结构），届时再引入，且应只在 L1 路径上加载。

## 三、Token 坐标系：防止标注漂移的地基

### 问题

让模型指出"哪个词需要注释"时，它会：拼错原词、返回原文中不存在的形式、在同一个词出现多次时无法指明是哪一处、擅自改写或"顺手修正"原文。

字符串匹配定位在真实文本上失败率高得无法接受。

### 解法

**服务端先做确定性分词，给每个词一个全局编号。模型只被允许回引编号，永远不接触也不复述原文。**

```
原文：  The measure was widely seen as gerrymandering.

编号：  <0>The <1>measure <2>was <3>widely <4>seen <5>as <6>gerrymandering

模型输出：  { "first_token": 6, "last_token": 6, "note": "..." }

服务端：  token[6].start=34, token[6].end=48  →  回原文精确切片
```

### 数据结构

```
Token:
    id          全局序号（0-based，跨句连续）
    text        原文片段
    start,end   原文字符偏移
    sent_id     所属句子

Sentence:
    id, start, end, first_token, last_token

Document:
    text        原文（一字未改）
    tokens[]    仅包含单词，不含标点
    sentences[]
```

**关键设计**：`tokens` 只收单词，不收标点。跨词标注用 token 区间 `[first, last]` 表达，取 `tokens[first].start` 到 `tokens[last].end` 作为原文切片区间——**区间内的标点、空格、换行自然被包含且原样保留**。

### 服务端校验（必须实现，不可省略）

模型返回的每一项，全部满足以下条件才接受，否则**静默丢弃**：

1. `0 ≤ first_token ≤ last_token < len(tokens)`
2. `tokens[first].sent_id == tokens[last].sent_id`（标注不得跨句）
3. `last_token - first_token + 1 ≤ 12`（超长区间必是模型跑偏）
4. `note` 非空且长度 ≤ 40 字符
5. `kind` 在允许的枚举内

这套校验让"模型篡改原文"和"定位漂移"在架构上**不可能发生**，而不是"通常不发生"。

## 四、L0 词汇层：决策树

对每个 token 依次判定，任一步命中"跳过"即终止：

```
1. 读者白名单命中该 lemma            → 跳过（后验最高优先级）
2. 读者黑名单命中该 lemma            → 强制标注，不参与密度截断
3. 全大写且长度 > 1（NASA/GDP/CEO）  → 跳过（缩写属 L1 文化层）
4. 首字母大写 且 非句首              →
       ├─ 词频 = 0  → 跳过（专有名词，如 Obama）
       └─ 词频 > 0  → 继续（可能是句中的普通词被引号/标题格式影响）
5. 词典查无此词                      → 跳过
6. 无中文释义                        → 跳过（有释义才有注释可写）
7. 词频 > 0 且 词频序 ≤ 读者阈值      → 跳过（读者应当认识）
8. 词频 = 0 →
       ├─ 有 collins 星级 / 考纲 tag / oxford 标记
       │      → 继续（真实词汇，只是缺词频数据）
       └─ 三者皆无 → 跳过（多半是专名、学名或词典噪音）
9. 进入候选池，稀有度 = 词频序（词频为 0 时取 60000）
```

**去重与截断**（候选池处理完后）：

```
① 按 lemma 去重，同一词只保留首次出现（PRD 原则 3）
② 强制标注项（黑名单）全部保留
③ 其余按稀有度降序排序，取前 (密度 × 词数 / 100) 个
④ 恢复为 token 顺序输出
```

第 ③ 步是 PRD 原则 2 的落点：**超纲文章不会退化成满屏注释，只会保留最难的那几个**。

### 读者阈值

```
rank_threshold = max(500, 读者词汇量)
```

下限 500 防止误配置导致连 the、of 都被标注。

## 五、L1 模型层：契约

### 职责边界

**只做词典结构上无法表达的三类：**

| 类型 | 判定标准 | 示例 |
| --- | --- | --- |
| `phrase` | 整体含义 ≠ 各词字面含义之和 | `take it with a grain of salt` |
| `grammar` | 结构本身构成理解障碍 | 倒装、虚拟语气、多重嵌套从句 |
| `culture` | 需要文本之外的背景知识 | 典故、梗、时事指涉、机构别名 |

**明令不得输出**：单个普通生词的释义（那是 L0 的活，重复且更差）。

### 输入格式

```
[S0] <0>The <1>measure <2>was <3>widely <4>seen <5>as <6>gerrymandering
[S1] <7>Critics <8>called <9>it <10>a <11>Hail <12>Mary <13>pass
```

### 输出 Schema

```json
{
  "annotations": [
    {
      "first_token": 11,
      "last_token": 13,
      "kind": "culture",
      "note": "橄榄球术语：绝望中的最后一搏",
      "detail": "源自美式橄榄球比赛结束前的长传博弈，现泛指成功率极低的最后尝试。",
      "domain": "sports",
      "difficulty": 3
    }
  ]
}
```

| 字段 | 约束 |
| --- | --- |
| `first_token` / `last_token` | 必须通过第三节的五条校验 |
| `kind` | `phrase` / `grammar` / `culture` 三选一 |
| `note` | **≤ 20 个中文字符**，行内显示用，越短越好 |
| `detail` | ≤ 100 字，点开才看 |
| `domain` | 12 个领域标签之一或 `null`，供 L2 过滤 |
| `difficulty` | 1–5，供 L2 密度截断排序 |

### 关键约束（写进 prompt）

1. 输出严格 JSON，无额外文字
2. **只能引用给定的 token 编号，不得复述或改写原文**
3. 宁缺毋滥：整篇没有值得标注的，返回空数组
4. 单篇上限 8 条（超出说明标准放得太松）
5. `note` 用中文，且是**解释不是翻译**

### 调用策略

- **每篇一次调用**，不分段（保留全文上下文，文化背景判断依赖它）
- 超长文本（> 2000 词）按段落切分，各段独立调用
- 失败或超时 → **降级为纯 L0**，不阻塞阅读。L1 是增强，不是依赖

### 成本估算

| 项目 | 量级 |
| --- | --- |
| 800 词原文 | 约 1,000 tokens |
| 加编号后（约 2.5×膨胀） | 约 2,500 tokens 输入 |
| 输出 5–8 条标注 | 约 400 tokens |

代入当时的模型定价即可得单篇成本；国产主流模型量级在**分币级**。

**缓存后边际成本趋近于零**——这是候选/过滤分离的直接回报。

> 模型服务商的商用条款与数据留存政策需在接入前核实（见可行性档案待核实清单）。

## 六、L2 个性化过滤

唯一读取读者模型的地方。按序执行：

```
1. 丢弃 domain 命中读者"熟悉领域"的 culture 类标注
2. 丢弃与 L0 标注 token 区间重叠的 L1 标注（避免同一处双重注释）
3. 合并 L0 + L1 候选池
4. 按 (强制项优先, 稀有度/difficulty 降序) 排序
5. 截断至密度预算
6. 恢复 token 顺序输出
```

第 1 步是"知识储备"这一维的实际落点：勾选了"宗教神学"的读者，圣经典故注释全部消失；没勾"体育"的读者，`Hail Mary pass` 的注释保留。

## 七、渲染方案

### 按标注切分，不按词切分

朴素做法是把每个词渲染成独立节点以便绑定事件——**这是错的**，800 词文章会产生 800 个节点，在小程序端会明显卡顿。

正确做法：**连续的无标注文本合并成一个节点，只有被标注处单独成节点。**

```
片段序列 = [
  { type: "plain",  text: "The measure was widely seen as " },
  { type: "anno",   text: "gerrymandering", note: "改划选区", id: 3 },
  { type: "plain",  text: ". Critics called it a " },
  { type: "anno",   text: "Hail Mary pass", note: "最后一搏", id: 7 },
  ...
]
```

**节点数 ≈ 标注数 × 2 + 1。** 800 词 / 40 处标注 ≈ 81 个节点，各端均无性能压力。

### 视觉规范（PRD 原则 4）

```
正文       16px / 行高 1.9 / 深灰 #2b2b2b
注释       11px / 浅灰 #9a9a9a / 紧跟词后，无空格
标注词     不加粗、不变色、不加下划线
           —— 仅靠其后的灰色小字提示，视觉噪音最低
点击热区   标注词 + 注释整体，≥ 44×44 px（移动端可点性下限）
```

渲染效果：

```
The measure was widely seen as gerrymandering(改划选区). Critics
called it a Hail Mary pass(最后一搏) — an attempt with almost no
chance of success.
```

**为什么不用上标（ruby）**：视觉上确实更沉浸，但各端都没有可靠的原生支持，用 flex 模拟会破坏文本自动换行与行高一致性，移动端尤其糟糕。行内跟随方案换行天然正确、各端实现一致、改动成本最低。

> 若未来要试上标方案，应作为可切换的渲染器实现，而不是替换。

### 交互

- 单击标注 → 就地弹出轻量气泡：`detail` 全文 + 两个按钮「认识了」「还是不认识」
- 点击按钮 → 气泡消失，**当前页面即时重渲染**（认识的词注释立刻消失）
- 长按任意词（未标注的也可）→ 手动查词，同时记入黑名单

最后一条是漏标的兜底通道，让 PRD 原则 1 的"宁可漏标"有安全网。

## 八、数据模型

### 词库（只读，与用户数据严格分离）

```
stardict.db   903 MB   ECDICT 原样，只补三个索引：
                       idx_frq / idx_bnc / idx_collins
                       （原库仅有 word 索引，频带抽样必须补）
```

只读模式打开（`file:...?mode=ro`），多线程并发查询安全。

### 用户库

```
profile
    vocab_size          估计词汇量
    density             注释密度（每百词）
    domains             熟悉领域标签，JSON 数组
    repeat_annotations  同词是否重复标注，默认否

word_verdict
    lemma       PRIMARY KEY
    verdict     'known' | 'unknown'
    updated_at
    source      'feedback' | 'vocab_test'

document                        ← 读者自己的材料，可存全文
    id, title, text, word_count, created_at

annotation_cache                ← 跨读者共享，只存标注不存原文
    text_hash   PRIMARY KEY     sha256(规范化文本)
    layer       'L1'
    payload     JSON，token 区间 + 注释
    model, created_at

reading_log
    doc_id, finished_at
    annotation_count
    manual_lookups              读者主动查词次数 ← 北极星指标原始数据
    felt_density                读者主观评价：太多 / 合适 / 太少
```

`document` 与 `annotation_cache` 的区别是有意的：前者是读者的私人材料（可存全文），后者是跨读者复用的加工结果（**不存全文**，见 PRD 决策 4）。V1 单用户时区别不明显，但架构必须先分开，否则日后无法多用户化。

`reading_log` 的后两个字段是北极星指标的数据来源，**V1 就要埋**，否则无从判断系统是否真的在变好。

## 九、API 设计

```
POST   /api/documents          提交文本，返回 doc_id + 分片序列（含标注）
GET    /api/documents/{id}     重新获取，支持 ?density= 覆盖，走缓存不重算
DELETE /api/documents/{id}

POST   /api/feedback           { lemma, verdict }  即时写入白/黑名单
GET    /api/profile
PATCH  /api/profile            改词汇量 / 密度 / 领域标签

POST   /api/vocab-test/start   返回首题
POST   /api/vocab-test/answer  { session, word, known } → 下一题或最终估值

POST   /api/lookup             { word }  长按手动查词
GET    /api/reading-log        北极星指标回顾
```

**关键**：`GET /api/documents/{id}?density=2.5` 必须**只走 L2 过滤**，不重新调用 L0/L1。这是密度滑块能即时生效的前提（PRD 决策 1）。

## 十、词汇量自适应测试

### 频带划分（基于 COCA 词频序）

```
1K  2K  3K  5K  8K  12K  20K  30K
```

超过 47,062（实测 COCA 上限）无数据，测试上界即封顶于此。

### 算法

```
lo, hi = 1000, 30000
每轮：
    band = 几何中点  √(lo × hi)
    从该频带抽 5 个词（要求有中文释义、非专名、纯小写字母）
    读者判断"认识 / 不认识"
    认识 ≥ 4 个  → lo = band   （水平更高）
    认识 ≤ 1 个  → hi = band   （水平更低）
    其余         → 收敛，取 band
直到 hi / lo < 1.5 或 已出 5 轮（25 题）
```

**几何中点而非算术中点**，因为词汇量的感知差异是对数尺度的：4000→6000 和 12000→18000 的难度跨度相当。

### 出题形式

显示英文词 + 音标，读者二选一「认识 / 不认识」。**不做选择题**——四选一的猜对率 25%，会系统性高估；自评的偏差反而更小且成本低得多。

### 抗作弊

每个频带混入 1 个**伪词**（形态合法但不存在的词，如 `flenzible`）。若读者声称认识伪词，说明存在系统性高估，最终估值下调一档。

> 伪词表需人工构造 20–30 个，或从词库中筛选零词频且无释义的条目改造。V1 可先不做，但接口要预留。

### 测试结果的处理

估值写入 `profile.vocab_size`，同时把测试中判定"认识"的词写入白名单（`source='vocab_test'`）。**测试本身就是第一批反馈数据**，不要浪费。

## 十一、技术栈

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端 | Python 3.12+ / FastAPI | 作者最熟；异步适合模型调用；类型友好 |
| 词库 | SQLite 只读 | 903MB 单文件，零运维，查询毫秒级 |
| 用户库 | SQLite | V1 单用户，够用。多用户时迁 Postgres，接口不变 |
| NLP | **不引入** | 见第二节"为什么不用 spaCy" |
| 模型 | 可插拔 provider | 抽象成接口，默认国产（备案与延迟考量），不锁死厂商 |
| 前端 | 原生 HTML + 少量 JS | V1 不引入构建工具。产品重心在引擎，前端只是渲染分片序列 |

### 部署形态

- **V1**：本机 `localhost` 跑，够用。不要过早上云
- **V3**：需要备案的大陆境内服务器（若走小程序），或海外 + Stripe（若走欧美路线）
- 词库 903MB 不进 git（`.gitignore` 已配置），通过脚本从 GitHub Release 拉取重建

## 十二、已知风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 词频序不等于真实难度 | 少数常见词被误标 | 靠反馈白名单快速收敛；这正是后验设计的用途 |
| 一词多义 | 行内注释给的可能不是本句义项 | V1 接受此缺陷（取最主要义项）。V2 可让 L1 对高频歧义词补充语境义项 |
| 零词频词的取舍 | 可能漏标真生词 | 长按手动查词兜底，且会自动进黑名单 |
| 模型注释质量不稳 | 文化背景注释可能失准或啰嗦 | 严格的 note 长度上限 + 单篇 8 条上限；读者可一键关闭 L1 |
| ECDICT 释义质量参差 | 部分词的中文释义生硬 | 可接受。行内注释只需"够用于不打断"，不追求词典级精确 |
