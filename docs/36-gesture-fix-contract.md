# 翻页状态与回弹修复：编码前失败清单

基线：`outputs/wise-reader-gesture-matrix-20261007`，112 个记录 / 109 个有效，取消回弹最大单帧进度 18%，280ms 连翻与交替吞手势。

## 修复约束

- 90ms 无输入开始可撤回的自动预览；240ms 流边界继续用于确认/分割手势。240ms 前不得提交页码或锚点，避免先前简单缩短停手阈值导致误翻。
- 同一手势恢复输入必须继续当前可见纸张，不能跳回旧进度、反向移动或丢累计位移。逻辑位移用于判定提交，视觉偏移用于衔接已移动的纸张。
- 新手势抵达旧动画结束之前必须保留；按先后顺序完成，每手势一页/跨页。排队后的首帧/追赶必须限定位移，避免用突然跳转换取计数正确。
- 取消/完成使用对称平滑曲线和与行程对应的时长，避免短 cubic ease-out 把过半回弹压成大步跳变。目标：取消最大单帧进度低于 10%，至少不劣于基线上版的 13.8%；收尾提交帧间隔 p95 <34ms 是独立门槛。
- 自动画面可动，但未确认前原文、页码和锚点不动；回滑、慢 1px 回滑、不足半页仍不提交。
- 无动画/减少动态效果、纹理未就绪时也必须等确认，不因无 GPU 场景在 90ms 提交。
- 排队期间取消、打开工具、选区、词卡、缩放、重排、路由离开、失焦必须清队列和计时器；不得有迟到提交或跨书泄漏。确认后跨章仍沿用原导航，无伪造章节纸张。
- 纸边拖动、点击、键盘原策略不变；只有触控板使用新衔接/曲线。光影、网格、纹理分辨率和缓存预算不降低。

## 验证与停止条件

先运行现有触控板专项及新增暂停恢复/取消接续守卫；预热软件 GPU 输入需记录真实空档，不能将自动化断流当成正常触控板。

同样的原生 wheel 增益校准和 M4/Metal/Retina 条件下，重跑慢/中/快三速度、四场景、单/双页、280/400/600ms 的修复矩阵；基线上版数据直接使用已保存原始记录，不再耗时重测未改的旧模块。输入失效样本保留并排除功能判断，生成逐样本对照。

同一阻塞最多两次无进展即停止该环境。完成业务开发后才跑一次完整回归，保留失败，不更改旧软件 GPU 的帧率门槛。本轮不写单元测试。交付复现命令、运行环境、原始 JSON/CSV、源码 SHA256 和正式服务/阅读位置证据。

## 实现细节与验证迭代

触控板完成/取消改为 smoothstep，完成时长 160–360ms，取消按剩余行程 180–480ms；停手 90ms 开始预览，240ms 前禁止提交。遇到晚帧，自动收尾每次提交最多推进 0.065，继续 RAF 到真正终点，避免时间已到便跳到原文下一页；排队追赶每次最多 0.06。指针/键盘曲线保持。

首次测试启动失败：Playwright 的 worker 级 channel 不可在 describe 内设定，拆分了独立硬件守卫文件，并保留启动错误。第一次实际专项 12/13 通过，反向恢复断言拿早于输入的 pin 与数百毫秒后的回弹点比较，观测跨越了整个取消阶段；改为同一 wheel 事件前后首个 RAF 的 pin 快照，收紧位移上界到 100px，三个硬件守卫全部通过。不是将真实跳变阈值放宽。

快速矩阵两布局共 12 个样本通过，280ms 连翻/交替逐次正确；正式完整修复矩阵只重测 current，前一轮基线保存作数值对照。
