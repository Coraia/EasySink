#### Q3 用用户操作澄清

| 概念 | 拟议用户操作或既有操作 | 含义 |
|---|---|---|
| 导入 PDF | 在本机 Web 阅读器点击导入并选择文件 | 浏览器将文件交给同一台电脑上的阅读服务；这不等于发送给外部服务 |
| 将整本 PDF 发送到外部服务 | 在拟议的外部识别入口明确选择某个服务并确认发送内容 | 完整文件离开当前电脑；也可能以所有页面图像的形式发送，不能因拆页就描述为仅发送局部内容 |
| 外部服务转换 | 在拟议入口选择由另一台机器或第三方服务识别 | 外部服务做 OCR、版面、公式或表格识别并返回阅读用内容；这是处理发生的位置，不是整书翻译 |
| 选区 AI 翻译/解释 | 在阅读时选中词句，主动点击翻译或语境解释 | 使用已配置的模型处理所选文字及必要的有限上下文；不因此发送整本 PDF |

本机转换需要的模型下载是接收模型资源，不是发送用户文档。文件是否外发与计算是否在外部是两件事：发送原件可用于保存而不转换；外部转换也可能只处理用户选定的页或区域，不必发送整本文件。

用户进一步询问："这里的外部，也包括 llm api是吗"。澄清：向云端 LLM API 发送 PDF、页面图像或提取文字进行识别/结构整理，属于外部处理；API 若连接这台 Mac 上运行的本地模型，则属于本机处理。用户自己的另一台机器或服务器也属于当前定义的外部，但不一定是第三方。判断依据是内容是否离开当前电脑及处理实际发生的位置，不是是否使用 API。

既有选区 AI 翻译/解释可能使用外部 LLM，但其发送范围与 PDF 转换的整本、指定页或指定区域不同。Q3 的推荐规则不等于禁止既有按需 AI 功能，也不将已有 LLM 配置视为自动发送整本 PDF 的选择。这次关于 LLM API 的追问是澄清定义，最终接受见下文。

当时重新表述 Q3：普通导入默认在本机处理，本机失败也不自动改用外部服务；只有用户明确选择外部处理，并确认目标服务和要发送的文件/页/区域时，才发送内容。是否接受这个默认规则？Q4 后续将这里的“确认”明确为用户处理操作本身，不增加独立确认步骤。

推荐：接受。是否在第一期提供外部转换入口、采用哪个服务、发送范围与收费方式均未决定；本次澄清不把该入口变成已开发或已批准的第一期功能。

最终回答（2026-10-08）："对，Q3接受建议，特别是llm这种付费接口，需要设计好范围和缓存、重放等"。决定：接受澄清后的默认规则，并增加付费接口范围、缓存及重放的设计要求。影响：补充 PDF 转换、本机转换、外部转换及已授权转换范围四个领域术语；记录 ADR 0002；开启 J、K、L 分支。未将具体付费策略或第一期外部入口自动视作接受。

## 第 2 轮：付费调用与导入质量

本轮四个问题的前提均来自已接受的 Q1–Q3，彼此的推荐不以其他本轮问题被接受为前提。收费异常重试、缓存保留/删除、预算计量和实际服务接口支持放到依赖已明确后的轮次；不要求用户猜测当前接口能力。

### Q4：付费调用的授权粒度

以下为原提案，已被用户修订；当前决定以本节的用户回答为准。

若启用付费外部处理，是否先选定页/区域，必要时显式选择整本；执行前看清服务与模型、完整发送范围（含必要上下文）、调用量及费用估计，并设置任务预算？一次授权覆盖范围和预算内的任务执行，不要求每一页重复确认；新增调用若超出授权范围或预计预算，需要重新选择。

推荐：是。范围与成本按任务管理，已有模型配置、阅读翻页或后台失败不能自动扩大付费任务。估算缺少可靠价格信息时应明确未知，不显示为零或承诺账单精准；预算拦截新增请求，不承诺取消已发出的请求就能退费。是否支持整本付费处理仍是后续范围决定。

用户回答（2026-10-08）："Q4: 否，在设计上，用户操作的时候就已经完成授权，不需要额外增加"。决定：拒绝原推荐中的额外授权/确认流程，采用含义清楚的用户处理操作直接授权对应调用，例如对已选页面执行外部识别，或明确选择重新生成。不要求额外点击授权弹窗、费用确认页或为每个任务先手工填写预算。

这次修订保留 Q3 的默认本机处理和明确发送范围原则；普通导入、已有模型配置、阅读翻页不自动扩大为任意外部转换。若用户以后选择不同范围，新的处理操作本身表达新的授权，不另外叠加确认步骤。成本信息的展示方式、后台限额、超时和结果未知时如何重试仍未决定；不把“无需额外确认”推断为无限调用、禁止费用信息或取消所有内部成本控制。影响：修订 ADR 0002 和已授权转换范围的定义，后续费用设计须遵循无重复确认的交互约束。

### Q5：区分结果复用、本地重放与重新生成

是否默认复用相同内容、范围和处理设置的已有有效结果；“本地重放”只用已保存的响应或中间产物重建阅读内容，不发起新的付费请求；“重新生成”才再次调用模型，并明确提示可能再次计费？

推荐：是。再次打开或重建排版不重复付费，重新生成保持为明确动作。失败结果不冒充成功缓存；换模型、内容或影响结果的设置需要识别为不同处理。没有足够重放材料时显示不能重放，不静默改为远程重新请求。本轮只确认这三个动作的语义，存储粒度、保存多久、版本兼容和去重细节后续再定。

用户回答（2026-10-08）："Q5、6: 是"。决定：接受推荐，默认复用匹配的有效结果；本地重放仅使用已保存响应或中间产物，不新发付费请求；重新生成是明确的新模型处理动作，可能再次计费。没有重放材料不能静默改成外部请求。按照 Q4，重新生成的业务操作本身即授权，不增加费用确认弹窗。影响：新增对应术语；存储粒度、结果版本、保留/删除和收费不确定性进入后续轮次。

### Q6：逐步开放可读内容

是否在 PDF 原件成功接收并校验后就保留一个书架条目，明确显示转换状态；原版可用时先允许核对，已经完成转换与检查的内容可先进入阅读版，剩余部分继续处理，不必等待整本结束？

推荐：是。显示“原版可查看”“阅读版已就绪范围”“其余处理中”等不同状态，不把原版首屏出现当成全文转换完成；书架保存不依赖点击“开始阅读”。具体引擎能否按此交付需验证，后台新结果与正在阅读内容的切换在后续轮次明确。

用户回答（2026-10-08）："Q5、6: 是"。决定：接受推荐，原件接收并校验后保留一个书架条目，明确显示转换状态；原版先可核对，转换和检查完成的范围逐步开放阅读，其余继续处理，书架保存不依赖点击“开始阅读”。这是产品目标，尚不代表某个转换引擎已经被验证具备渐进交付能力。影响：新增阅读版就绪范围术语；任务状态、后台调度和当前阅读内容如何更新进入后续轮次。

### Q7：局部识别失败的回退

用户回答（2026-10-08）："全部接受"（对应 Q14–Q19）。决定：接受推荐，内容完全相同的 PDF 再次导入回到已有书籍，复用有效结果或既有任务，不新增重复书籍或付费调用。影响：后续设计原件身份与导入去重；不按书名/文件名合并，也不自动承诺不同内容或仅视觉相似文件的合并。

### Q17：删书与恢复

是否删除书籍先进入可恢复状态并停止其后续转换，保留原件、阅读记录和已有结果供撤销/恢复；彻底释放资料通过明确的清理操作进行？

推荐：是。迟到转换结果不能让已删除书籍重新出现在书架，恢复不能自动重跑曾取消或结果未知的付费尝试。恢复保留的有效结果，不因此重新计费。回收期限、恢复后是否继续尚未完成的本机任务及永久清理的操作表达后续细化；不在本轮删除任何真实书籍。

用户回答（2026-10-08）："全部接受"（对应 Q14–Q19）。决定：接受推荐，删书先进入可恢复状态、停止后续转换，并保留原件、阅读记录及已有结果；永久释放通过明确清理操作进行。迟到结果不使已删除书籍重新上架，恢复已有结果不新增付费请求，曾取消或结果未知的付费尝试不自动重跑。影响：新增书籍回收与恢复术语；保留期限和磁盘不足策略在 Q21 细化，恢复后未完成本机任务的状态在方案中明确。

### Q18：对阅读版原图记笔记

是否阅读版里的图片、公式或表格原图也能直接记笔记，引用对象是该图及其原页区域，不要求先识别成文字？

推荐：是。保持与现有笔记一致的新增、编辑、删除撤销和定位体验；图像引用与文字选区区分，不能伪造为已经识别的文字。此题针对阅读版的就地原图，原版工具范围独立由 Q19 决定。

用户回答（2026-10-08）："全部接受"（对应 Q14–Q19）。决定：接受推荐，阅读版图片、公式或表格原图可直接记笔记，引用该图和原页区域，不要求先转成文字；沿用新增、编辑、删除撤销与定位体验。影响：新增原图笔记术语；后续设计图像引用及来源锚点，不把原图笔记扩大为原版完整笔记工具。

### Q19：第一期原版的学习工具范围

是否第一期原版主要提供查看、缩放、原页/区域定位、选择处理目标和返回阅读位置；查词、译文联动、语法分析及阅读笔记继续集中在阅读版，暂不在原版复制整套学习工具？

推荐：是。Q2 确定了两种视图的主次，此题明确第一期工具范围；选择处理页/区域可以服务本机重新识别，不以 Q14 接受外部入口为前提。这样原版先做好核对，阅读版可用范围沿用完整理解辅助。原图区域缺少可靠文字时不假装能逐词操作，后续原版学习能力需另外决定并验证文字坐标；旧格式及既有阅读功能的范围不收缩。

用户回答（2026-10-08）："全部接受"（对应 Q14–Q19）。决定：接受推荐，第一期原版负责查看、缩放、来源定位、选择处理目标和返回阅读位置；查词、译文联动、语法分析与阅读笔记集中在阅读版，不在原版复制整套学习工具。影响：确定原版查看器与范围选择的产品边界；原图回退不被冒充为逐词可交互内容，旧格式及原有阅读功能不收缩。

## 第 5 轮：纠错、保留与交付取舍

Q14–Q19 已由用户全部接受。本轮五题均只依赖已明确的前置决定：Q20 依赖版本更新和失效正文处理；Q21 依赖资料保留、任务与删书恢复；Q22 依赖本机处理、开源复用和上游初步核对；Q23 依赖既有产品边界及功能/性能不退步要求；Q24 依赖局部外部增强、非阻断成本反馈与未知结果规则。本轮答案不互为前提。

### Q20：可选的局部文字纠错

以下为初始提案，已由后续事实核对和用户反馈修订；当前决定以本节最终回答为准。

第一期是否允许读者在阅读版里主动修正少量识别错误，保留原 PDF 与原识别结果，并保护手动修正不被后续自动重识别覆盖？

推荐：是。纠错是按需能力，不把读者校对整本书变成可阅读的前提；修正不会改写原 PDF。后续结果与手动修正冲突时保留修正，不静默替换；原文来源和笔记引用应能回溯，具体映射需验证。不把此能力扩大为完整文档编辑器或自动补写书籍内容。

首次追问（2026-10-08）："Q20: 这个怎么实现？给我一个沉浸式阅读产品这样做的样例参考（如有） 其他"。这次追问当时不是接受 Q20，最后的“其他”当时也没有明确对应 Q21–Q24 的答案，故保留未定并另行澄清；后续明确答复见下文。

追问核对见 [局部纠错参考与实现说明](52-pdf-correction-reference.md)。Speech Central 的官方旧文章支持“应用内正文编辑”的相近能力参考，但没有核实具体 OCR 纠错流程；Readwise 和 NaturalReader 的摘录/批注编辑不能冒充正文修正。局部卡片、另存修正和来源映射只作为候选设计，不能因参考说明自动纳入首期。

修订推荐：手动纠错保留为备选；首期优先保证识别质量、原图核对和已接受的局部重新识别，是否提供手动纠错入口依据实际错误样本及后续交互原型再决定。

最终回答（2026-10-08）："Q20接受修改后的建议，其他采纳建议"。决定：接受修订推荐，手动纠错未自动列为首期交付内容；优先完成识别、原图核对和局部重新识别。影响：T 分支的当前范围选择已闭环，备选纠错交互与技术说明继续保留，不作为已批准或已实现的功能；将来若纳入需再明确范围与验收。

### Q21：空间不足与资料保留

是否默认不按保存天数自动删除原件、阅读记录、有效结果、重放资料及可恢复的书籍；空间不足时只清理可本机重建的临时资源，仍不足则暂停新增转换并提供空间管理入口，由读者明确清理保留资料？

推荐：是。保留资料不因磁盘压力被悄悄丢弃，也不承诺无限空间；容量阈值及预留空间由实测确定。恢复书籍先恢复原件、记录与有效结果，未完成且因删书停止的本机任务保持暂停，由“继续处理”操作恢复，避免恢复动作立刻占用阅读资源；取消和未知付费请求仍按 Q11、Q15、Q17 处理。设置保存期限或自动清理重要资料不作为默认策略。

用户回答（2026-10-08）："Q20接受修改后的建议，其他采纳建议"（“其他”对应 Q21–Q24）。决定：接受推荐，默认不按保存天数自动删除重要资料或可恢复书籍；空间不足只清可本机重建的临时资源，仍不足暂停新增转换并提供空间管理入口。恢复书籍恢复已有资料，因删书停止的未完成本机任务保持暂停，通过“继续处理”恢复。影响：默认保留、恢复与磁盘压力行为确定；具体空间阈值待测量，不在本轮执行清理。

### Q22：一套主转换流水线与可替换边界

是否第一期只接入一套经过同样本比较后选出的本机主转换流水线，为其他组件留可替换接口，而不把 Docling、MinerU、PaddleOCR 三套完整环境都默认装入产品？

推荐：是。复用现有开源组件，原版显示优先评估 PDF.js；候选主引擎用相同本机、相同材料对比质量、来源定位、资源、渐进交付及许可后确定，不能仅凭榜单定案。一套流水线可以包含必要的 OCR、版面和公式模型，不等于只能用一个模型；也不排除 Q14 已接受的主动局部增强。具体组件版本与模型选择由事实验证决定，不要求用户猜性能。

用户回答（2026-10-08）："Q20接受修改后的建议，其他采纳建议"（“其他”对应 Q21–Q24）。决定：接受推荐，首期默认接入一套实测选出的本机主转换流水线，保留其他引擎的替换边界，不默认安装三套完整环境；一套流水线可包含必要的多个模型，局部外部增强继续按 Q14 提供。影响：记录 ADR 0006；具体主引擎、模型和版本仍由相同条件的样本比较与许可核对决定，当前不安装或执行。

### Q23：验收不达标时的交付边界

是否先以真实材料验证转换方案、再提供交互原型；转换质量或既有阅读功能/性能未达标时，保留在实验阶段，不因“已经能导入 PDF”就进入正式版本？

推荐：是。材料应覆盖用户实际英文书籍，以及有使用权的扫描、公式、复杂表格/版面和混合语言样本；原有 EPUB/TXT/Markdown 路径也要做最终回归。区分模型冷启动、已有模型的首次导入、原版首屏、首段阅读版可用和全书完成的时间；分别比较无转换与后台转换时的旧书打开、翻页帧耗时、清晰度、笔记/书签定位，保留首次失败和可复现报告。可交互原型经用户验收后再进入功能开发；实际材料路径、冻结版本、测量方法、误差容差与数值门槛在实验开始前写明，不在本轮把尚未测量的目标当事实。

用户回答（2026-10-08）："Q20接受修改后的建议，其他采纳建议"（“其他”对应 Q21–Q24）。决定：接受推荐，先以真实材料验证转换方案，再提供交互原型并由用户验收；质量或既有阅读功能/性能未达标则不进入正式版本。影响：下一阶段顺序、旧格式回归、后台转换负载下的阅读验证和可复现证据要求确定；实验前需写明样本、版本、数值门槛及容差，未测量的目标不当作事实。当前仍只更新文档，不自动进入实验或代码开发。

### Q24：第一期付费限额的计量方式

是否第一期提供可选的 PDF 外部处理调用次数上限，费用按可核实的价格和实际用量记录或估算；暂不承诺供应商级精确金额硬限额，也不让 PDF 的限额默默阻断原有阅读 AI 功能？

推荐：是。默认不要求用户填写额外预算，也不设置未告知的隐含硬限额；用户可在设置启用调用次数上限，达到时暂停新的未发请求，修改限额或明确继续就是业务操作，不增加确认步骤。仅统计新增付费请求，结果复用和本地重放不占调用次数；已经发出而结果未知的尝试暂计入次数，不能按失败免费释放。价格或用量未知时明确标记未知，金额估算不能冒充准确账单；并发预留、实际调用核对和服务能力在方案与验证中细化。

用户回答（2026-10-08）："Q20接受修改后的建议，其他采纳建议"（“其他”对应 Q21–Q24）。决定：接受推荐，首期提供可选的 PDF 外部调用次数上限，可靠费用与用量如实记录或估算、未知明确标注，不承诺精确金额硬限额；PDF 的限额不默默阻断原有阅读 AI。默认不要求额外预算或设置隐含硬限额，达到已设次数上限暂停新的未发请求；已发结果未知的尝试暂计入次数，复用和本地重放不计入。影响：一期计量边界确定；并发预留、供应商用量与费用核对、继续处理的界面表达在详细方案中细化，不增加授权或费用确认。
