# 里程碑与验收标准

> 每个里程碑都给出**可判定的**通过标准。不接受"做完了"这类主观描述——
> 验收人只需按"验收方法"执行一遍，对照数字或是/否即可下判定。

---

## 验收基准集（先准备，后开发）

在 M1 开工前，先手工准备 **5 篇真实文章**作为回归基准。此后每个里程碑都用同一批文章验收，才能看出系统是变好还是变坏。

| 编号 | 类型 | 长度 | 选取要求 |
| --- | --- | --- | --- |
| A | 技术文档 / 工程博客 | 600–1000 词 | 专业词密集，作者本人熟悉的领域 |
| B | 外刊时评（经济学人 / 大西洋月刊） | 600–1000 词 | 长难句多，含政治时事指涉 |
| C | 神学 / 人文著作节选 | 600–1000 词 | 作者熟悉领域，用于验证"熟悉领域不该被标注" |
| D | 体育 / 流行文化报道 | 600–1000 词 | 作者陌生领域，梗和俚语密集 |
| E | 小说节选 | 600–1000 词 | 叙事文体，习语和非正式表达多 |

**同时人工标注一份"标准答案"**：逐篇列出作者本人**确实不认识**的词、以及**确实需要背景说明**的表达。这份人工答案是后续一切准确率计算的分母来源。

> 这一步大约耗时 2 小时，但它是整个项目唯一能客观判断"是否变好"的依据。不做这一步，后面所有验收都会退化成凭感觉。

## M0 · 地基

**交付物**：Tokenizer + 词典层。无界面，提供命令行查询。

**验收方法**：对 `03-design.md` 第二节的「实测样例表」逐行验证。

**通过标准**（全部必须满足）：

- [ ] 10 个样例词的词形还原结果与样例表完全一致
- [ ] `they` 还原为 `they` 而非 `it`（反向映射冲突已处理）
- [ ] `Obama` 的词频返回 0
- [ ] 行内注释已剥离 `n.` `vt.` 等词性前缀
- [ ] 对基准集 5 篇文章分词，**原文可从 token 偏移无损重建**（逐字符比对通过）
- [ ] 分句不被 `Mr.` `U.S.` `3.14` 切断

> 最后两条是地基的核心。原文无损重建若不通过，后面全部会歪。

## M1 · L0 词汇标注

**交付物**：给定文本 + 词汇量，输出标注列表。仍无界面，命令行打印带注释的文本即可。

**验收方法**：词汇量设为 8000、密度设为 4，跑基准集 5 篇，人工逐条核对。

**通过标准**：

| 指标 | 定义 | 通过线 |
| --- | --- | --- |
| 专有名词误标数 | 人名/地名/机构名被标注的处数 | **= 0** |
| 密度合规 | 实际标注数 ÷ 词数 × 100 | **≤ 4.5**（允许 0.5 的取整余量） |
| 同词重复 | 同一 lemma 在一篇内被标注 > 1 次 | **= 0** |
| 误标率 | 作者**认识**却被标注的词 ÷ 总标注数 | **≤ 15%** |
| 漏标率 | 作者**不认识**却未被标注的词 ÷ 作者不认识的总词数 | **≤ 40%** |

**关于两个比率的不对称**：误标线（15%）远严于漏标线（40%），这是 PRD 原则 1 的直接量化。漏标有长按查词兜底，误标没有补救——它直接毁掉沉浸感。

**若误标率超标**，优先检查：零词频词条的兜底策略是否太宽松、首字母大写判定是否失效。

## M2 · Web 阅读界面与反馈闭环

**交付物**：可在浏览器粘贴文本、阅读、点击反馈的完整闭环。

**验收方法**：作者本人用它完整读完基准集 5 篇。

**通过标准**：

- [ ] 行内注释视觉符合 `03-design.md` 第七节规范（11px 浅灰、紧跟词后、标注词本身无任何装饰）
- [ ] 一篇 1000 词文章渲染后 **DOM 节点数 < 200**（验证"按标注切分"确实生效）
- [ ] 点击注释 →「认识了」→ **该词注释在当前页立即消失**，无需刷新
- [ ] 反馈落库，重开新文章时该词不再被标注
- [ ] 密度滑块拖动 → **500ms 内**重渲染完成，且**无网络请求发往 L0/L1**（证明只走 L2 过滤）
- [ ] 长按未标注词可手动查词，并自动记入黑名单
- [ ] `reading_log` 记录了主动查词次数与主观密度评价

**M2 是真正的分水岭。通过标准之外，还有一条主观判定：**

> **作者本人是否开始每天用它读英文，而不是回到原来的方式？**

若答案为否，不要进入 M3。停下来找原因——是标注质量不行，还是交互有摩擦。**这个问题的答案比上面所有勾选框加起来都重要。**

---

## M3 · 词汇量测试

**交付物**：自适应频带测试。

**验收方法**：作者本人做 3 次测试，中间间隔至少 1 天。

**通过标准**：

- [ ] 25 题内收敛
- [ ] 3 次结果的极差 **< 20%**（重测信度）
- [ ] 结果与作者自我估计处于同一量级
- [ ] 测试中判定"认识"的词已写入白名单（`source='vocab_test'`）
- [ ] 可跳过测试，改用考纲自评或直接输入数字

## M4 · L1 模型层

**交付物**：习语 / 语法 / 文化三类标注。

**验收方法**：跑基准集 B（时评）和 D（体育流行文化）——这两篇 L1 价值最高。

**通过标准**：

| 指标 | 通过线 |
| --- | --- |
| token 区间非法率（被校验丢弃的比例） | **≤ 5%** |
| 原文被改写的情况 | **= 0**（架构上应不可能，实际验证一遍） |
| 注释准确率（人工判定，不含事实错误） | **≥ 85%** |
| `note` 超长（> 20 中文字符） | **= 0** |
| 单篇标注数 | **≤ 8** |
| L1 服务不可用时 | **自动降级为纯 L0，阅读不中断** |
| 同文本第二次请求 | **命中缓存，零模型调用** |

**降级验证是必测项**：手动断开模型 API，确认阅读体验只是少了三类标注，而不是报错或卡死。

---

## M5 · 领域标签与完整 L2

**交付物**：12 个领域标签的勾选与过滤。

**验收方法**：用基准集 C（神学）和 D（体育）做交叉验证。

**通过标准**：

- [ ] 勾选「宗教神学」后，C 篇的宗教类背景注释**全部消失**
- [ ] 未勾选「体育」时，D 篇的体育类背景注释**全部保留**
- [ ] L0 与 L1 的 token 区间重叠时，只显示一处（无双重注释）
- [ ] 合并后总密度仍受密度预算约束

## 全项目终验

同时满足以下三条，V1 才算成功：

1. **北极星指标达成**：连续 5 篇 800 词文章，`reading_log` 中主动查词次数 **= 0**，且注释密度 **≤ 5%**
2. **持续使用**：作者本人连续 **14 天**日常使用，未回退到旧方式
3. **后验生效**：个人词表规模 **> 300 条**，且最近 5 篇的误标率相比 M1 验收时**下降了**

第 3 条验证的是这个产品的核心假设——**系统会随着使用越来越懂你**。如果误标率不随词表增长而下降，说明反馈闭环没有真正起作用，那么整个个性化设计需要重新审视。

---

## 验收时值得反复问的三个问题

1. **它是让我读得更爽了，还是只是让我看到了更多信息？**
   信息量增加不是目标，认知负担降低才是。

2. **我有没有因为注释太多而跳过它，直接读原文？**
   如果有，密度就是超了，不管指标显示什么。

3. **有没有出现"这个词标了但我早就认识"的恼火时刻？**
   这是误标率的体感版本，比统计数字更早暴露问题。
