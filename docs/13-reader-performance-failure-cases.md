# 阅读打开性能：改动前的失败风险与验收边界

基线：本机 Chromium，1379×1135，实际 `/read/10`，54,789 词。三次新浏览器上下文到 reader ready 为 2347/2354/2292 ms；全文分页为 1131/1134/1099 ms，文档请求 681/687/669 ms，布局约 14,402 次。原始证据保留在 outputs/wise-reader-performance-20261005/baseline.json。

目标：同一本书同一量测脚本，中位打开时间至少降低 50%；首屏不等待全文分页，后台分页每批让出主线程。另用百万字符的合成书验证首次显示与完整分页分离，不将合成数据写为百万词或微信读书对比实测。

必须覆盖的失败方式：
- 分页未完成时错误显示完整页数、不能翻到已就绪的下一页。
- 后台续排刷新当前正文、清除选择、笔记、译文或语法状态。
- 重排或离开书籍后旧异步任务覆盖新页面；旧恢复任务在用户翻页后抢回位置。
- 长段落、代码、中文注释和 UTF-16 字符出现丢字/重字或错误断页。
- 续读、书签、目录、搜索跳到尚未排出的部分时恢复错误。
- 字号、栏宽、辅助密度变化后仍采用旧页号或旧高度。
- 内容分析缓存混入用户反馈、密度或词汇档案，使保留/掌握注释不能立即更新。
- 缓存内容或 L1 注释变更后未失效；大书持续驻留导致内存无界增长。
- 精简正文响应破坏旧 API 使用方或选择/翻译/发音所需正文。

开发期仅运行相关 E2E；改动结束后运行全套。保留首次失败、源码快照、量测 JSON、截图和 Playwright trace。两轮量测若均无改进则停止扩散改动并重新定位，不凭主观体验交付。
