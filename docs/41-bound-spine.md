# 装订书的翻页约束

2026-10-07 用户指出斜向翻页时内侧角点离开中缝，形成散页效果，确认修改整条书脊约束。

## 改动范围

`page-fold.js` 原模型会卷起内侧材料边，并使用随进度变化的整页中缝平移。新模型先求自由圆柱曲面的内侧偏移，再按材料横向位置连续消除：权重 `(1-u)²` 在书脊为 1，在抓取外缘为 0。整个 `u=0` 装订边保持原来的 x/y/z；外缘仍沿已验收的可达抓取点运动。

中缝补偿仅按材料位置作用在远端，内侧不平移。透视作用于约束后的高度，书脊高度为 0，因此不会重新拉走装订边。光照法线由约束曲面的解析切向量求得，书脊接触阴影也使用固定中缝位置。

软件 GPU 使用 64×24 网格并省去额外的书脊接触阴影运算；纹理栅格密度与原有 400k 画布预算对齐，避免软件解码/上传远高于画布分辨率的页面。装订约束保持相同，书脊仍有 25 个顶点。硬件 GPU 保留 96×24 网格与完整光照、高清纹理。该降级减少软件开销，不改变高清硬件画面或输入手感。

这是连续曲面约束，没有增加覆盖裂口的遮罩、悬浮遮盖条或停止动画。没有修改触控板阶段、距离/回滑判定、停驻/收尾、队列、书籍内容、阅读位置或高清像素预算。历史独立原型保留原样，正式版是本次修改对象。

当折线没有跨过某个书脊高度时，该处偏移严格为零，直接走原圆柱曲面快路径；只有跨过内侧边时才计算绑定补偿。中缝接触阴影仅在附近像素计算，避免全画布执行额外指数运算。完整斜折仍使用相同连续约束，不是跳过装订。

## 验证方式

`?debug-spine=1#/read/<id>` 仅用于验收：在 WebGL 网格自身的 25 个内侧顶点上用同一顶点着色器绘制诊断线，不是 DOM 叠加线。E2E 解码实际截图，沿页面高度扫描诊断线，核对与静态装订边的屏幕位置。正常 URL 没有该标记。

`reader-spine.spec.js` 覆盖单/双页、向前/向后、上下折角，分别检查 35%、65%、85% 行程，共 8 场景、24 姿态。覆盖率要求 >97%、误差 ≤1.5 CSS px，另存无标线深折画面。Escape 撤销检查不提交阅读页。

首轮检测曾因诊断线经过黑色文字时抗锯齿降低亮度而失败。逐像素记录证明线仍存在，检测改为绿色通道差，不再用绝对亮度筛选；覆盖率和坐标阈值保持不变。首轮与像素诊断保留。
