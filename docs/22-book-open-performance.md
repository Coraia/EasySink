# 真实书籍打开性能（2026-10-05）

## 问题与修复

实际从书架打开 Python Pocket Reference，服务进程尚未分析该章时：正文接口约 1.33 秒，语音列表探测约 0.72 秒，恢复阅读及工具准备完成约 2.17 秒。旧的首屏/已缓存基准没有覆盖这一组合。

1. 词典用不同词形的批量查询和共享 exchange 行缓存，避免每个词反复往返 SQLite；释义按不同词形计算一次。批量查询与原查词使用同样的大小写、变形、词频和释义规则。工作集 4,000 词，SQL 批次 400，行 LRU 20,000。
2. 内容分析持久缓存在用户本地库 `wr_source_analysis`。键包含实际正文、L1 候选、分析代码和词库/词形文件版本；个人词汇、密度和反馈不缓存。词条元数据去重、token 坐标压缩保存，正文不另存一份。进程重启仍可重用；错误/损坏回退重算。上限 64 条/32 MiB，解压上限 16 MiB。删除文档清除对应缓存。
3. 朗读工具立即注册，本机语音发现后台进行；主动发音若仍在检测则显示可取消的加载状态。错误可重试；离开页面或取消后不会继续播放或更新其他页面。

4. 路由的功能开关、读者档案和正文接口并行读取；插件安装仍然在 reader 挂载之前完成，页面切换仍用同一取消信号。

首次分析尚未有缓存的新章节仍需一次计算；导入时生成过分析的章节、已读章节重开及服务重启后的恢复可用持久缓存。没有把书籍的译文或个人反馈缓存成固定展示结果。

## 复查方法

- 运行 `.venv/bin/python scripts/web.py restart`，打开书架，点击 Python Pocket Reference。
- 在当前阅读器 DOM `.reader` 查看 `data-first-source-ms`、`data-ready-ms`、`data-pagination-ready`、`data-source-position`。`ready` 是恢复阅读位置并完成工具注册后经过两个动画帧；首屏 DOM 插入不是这个指标。
- 首次生成缓存、服务重启后恢复、同进程再开分别报告，不混合取最好结果。
- 分页可以后台继续，不以全章分页结束作为可以阅读的条件；对照注释完整响应、阅读锚点、页码、笔记等，而不是只验收 loading 字样消失。

失败边界、原始数据及重放证据位于 `outputs/wise-reader-open-python-20261005/`。生产数据不用于测试编辑/删除或触发云 AI。
