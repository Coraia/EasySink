# 翻页手感数值走查：测量前约定

用户要求按速度、完成、取消、连续、前后交替测量，不以单个耗时或主观描述宣称通过。此轮只增加可复现 E2E 测量与报告，正式阅读模块不修改。

## 矩阵与输入

- 对照：上一版 `trackpad-follow`（上次修改前备份的 pagination/trackpad 模块）与当前 `trackpad-release`。旧模块仅通过临时浏览器网络响应替换，不更改正式服务文件。
- 单页/双页；慢/中/快：纸页进度每秒 0.4 / 1.2 / 3，换算当前 travel 对应的像素。每约 33ms 送实际 native wheel；记录实际事件、合并与排程偏差，不把计划速度写成实际速度。
- 完成：前进 0.7 页；取消：前进 0.8 后回退 0.1（仍过半但应撤销）；连续：三次同向；交替：前后前后四次。常规手势间隔 600ms，另外压力测试 280ms / 400ms，观察输入是否被上一段结算吞掉。
- 每速度/场景/布局/版本常规重复两次，96 个常规样本；另外短间隔压力样本。单个样本无法推断稳定性，保留逐次结果和实际输入。
- 当前用户页为 GPU、单页、绘制比率 1.5。优先用本机 Chrome/Metal 的硬件 GPU 测相同产物，必须记录实际 GL driver；无法获得硬件时明确降级为软件证据，不能宣称是实际 Mac 触控板验收。

## 失败方式与数值证据

- 注入慢于计划/中间断流：计划与实际速度、最大事件间隔、事件合并、调度迟到；超出 25% 速度误差或段内事件空档超过 100ms 标记样本无效，不将其写成功能失败/成功。压力测试的主动空档单独标注。
- 跟手有延迟/模型已更新但纸未动：事件到下一次实际纸页 pin 更新与 RAF 观察的延迟；model 进度与可见 pin 换算进度差。合并的旧输入不单独计算过时延迟。
- 停手悬停：末次输入到首次自动收尾的时间；禁止把 240ms 无输入计时当作 GPU 掉帧。
- 收尾加速过猛/跳变：只统计连续收尾段的 RAF/实际 draw 帧间隔、归一化每帧位移、速度和加速度。位移大于 0.1 页/帧、连续动画 p95 超 34ms 标警告；这不是已获人工批准的物理体验标准。
- 取消失败或锚点改变：记录预期/实际提交序列、取消前后锚点、重复提交次数；取消不得提交。
- 下一手势开始时仍在结算，整个新手势被吞：在 280 / 400 / 600ms 间隔下记录实际 wheel 数、模型更新数、页码序列和预期提交次数。不能只看最终页码，交替丢两次可能巧合回到原位。
- 首次纹理/着色器准备、冷缓存和软 GPU：标注 GPU、窗口/布局、warm 指标；常规预热，冷启动/实际触控板硬件另列未验收。
- 一次手势横向连续误被拆开或惯性重复翻：实际事件流分段、提交序列、重复/丢失翻页。
- 测量探针/截图/trace 反而影响手势：trace 关闭，截图只在整批输入结束后；探针读取 DOM/原生输入事件，并旁路记录现有 WebGL uniform/draw 调用的进度与时刻（原调用仍执行），不调用业务方法。保留原始 JSON，量化监测开销与空闲 RAF 基线。

## 执行与停止条件

使用 18767/18768 的临时数据库及确定性 fixture，不碰用户书架/AI。先一次 GPU/排程校准（一个矩阵用例），有效后一次完整矩阵。最多两次同一环境无进展即停止该环境，不改门槛反复重跑。只读走查不运行与本次无关的全量功能套件；如后续进入业务修复，完成后才跑全量。

交付逐样本 CSV、原始 input/draw/RAF JSON、源码 SHA256、独立报告和复现命令。给出明确缺陷排序及适用的证据边界，不能用平均数掩盖丢手势或高分位卡顿。

## 校准证据与最终环境

首次校准实际 driver 为 Apple M4 / ANGLE Metal，浏览器 Chrome 154，33ms 输入节拍下实际事件最大间隔约 36ms；280ms 间隔出现连续提交 2/3、交替提交 2/4，且丢失手势 model 更新为零。这个红色结果是功能缺陷，硬件/输入校准已有效，进入一次完整矩阵而非重试取得绿色。

完整矩阵单页窗口匹配用户当前 796×1135，双页为 1440×1000；deviceScaleFactor=2，保持实际纸张最高 1.5 的绘制比率。校准 DPR=1 的数据另存，不混入正式汇总。新增 WebGL 提交侧记录包含末帧，避免 DOM pin 在同步落页时被移除而漏掉终点；RAF/pin 仍用于观察侧证据。提交调用、RAF 观察均不等于 OS 合成器实际展示时间或真实手指离开信号。

## Retina 输入增益校准与首轮排除

将 DPR 调到 2 后，第一轮完整矩阵收到的 native wheel deltaX 恰好为请求值的一半，0.7 目标只到约 0.35，三组完整数据均违反速度有效性门槛，不能把不提交计为产品失败。第四组浏览器在中途关闭，原因未确定，不编造 GPU 故障归因。第一轮保留在 `retina-input-mismatch`，不混入有效测量。

新增每个浏览器上下文的 native wheel 增益校准：发出 20，读取浏览器实际 delta，再用比值调整注入量。Retina 单页校准实测 observed=10、增益=2，正常完成/取消/600ms 连翻与交替符合预期，280ms 再次复现丢手势，输入和 GPU 校准已有效。只有这一步验证后才启动最终完整矩阵。逐样本立即落盘并保存环境，避免浏览器中断吞掉已完成证据；若浏览器关闭再次发生，不再重跑整批。
