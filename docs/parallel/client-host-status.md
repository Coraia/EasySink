## 实现前失败面与验证入口

- 当前没有可安装宿主，启动依赖仓库、开发 Python 和现场编译的触控桥：安装→导入→重开流程尚不可执行，作为本轮初始失败。
- 运行时或只读词库路径跟随仓库：在移出仓库的应用包中启动，记录完整资源成本。
- 误连固定端口/污染个人资料：独立资料目录，自有随机会话身份，绑定端口而非连接已运行服务；保留8766。
- 退出时写入丢失/进程孤儿：保存阅读位置，正常等待后端结束；崩溃由父管道关闭触发后端退出；重开通过界面回读。
- WebView 文件输入、下载、选区/纸面不兼容：使用真实 NSOpenPanel 导入，截图确认，不以 HTTP 导入代替原生文件入口通过。
- 新窗口导航或远端内容调用原生桥：仅自身 loopback origin 保留桥与阅读窗口，外部链接走系统浏览器。
- 原生触控手势与程序事件证据混淆：真正手势保持待真人验证，编译/注入检查只记为接线证据。
- 冷启动计时止于健康接口：记录原生启动和内容可操作的独立事件；健康仅为接入条件。

不新增单元测试；开发中不跑全套。最终直接走查及保存证据。

## 追加失败面：端口变更

后端切换端口时，WKWebView 的 origin 存储也变化，可能丢失排版、主题、笔记草稿与待提交位置。宿主只同步明确的阅读偏好/草稿键到隔离资料目录，在文档脚本执行前恢复；不复制凭据，也不恢复一次性跳转指令。写入失败必须使退出保存检查失败，不能声称草稿安全。退出前再次收集该白名单。原有 origin 存储首次接入后保留；后续以宿主存储为准，包括已删除键。

## 原生界面实际走查

在移出仓库的已安装应用中，通过真实 NSOpenPanel 导入两章示例 EPUB；不点击开始阅读而关闭导入窗，书仍在书架。进入默认专注、词卡、拖选、引用笔记、随记、书签、鼠标/键盘翻页及原生保存诊断入口均操作回读。输入完整中文笔记后立即 Cmd-Q，再打开仍可回读；下一轮重开后书签列表及跳回原段落可见。关闭窗口保留自有后端；重新打开窗口保持第3页。没有迁移个人8766书库。

公开论文65页通过真实文件入口进入当前电脑处理：首范围1396.658ms，范围全部转换38091.565ms；OCR=0、cloud_calls=0。转换结束65/65，但60页含局部原图回退，所以仅证明数字提取/显示集成，不宣布文字顺序、公式、选区翻译或扫描质量通过。原版核对渲染真实PDF、跳转原页13，返回阅读版恢复之前的阅读 spread。原始转换metrics保留；数据库updated_at在重启也更新，不能用它减created_at充当转换耗时。

首次加载提示残留来自宿主误用导入框内部选择器作为书架信号，修为#new-reading并将Web壳加载与可读里程碑分开记录。一个暖重开记录约1.63秒到正文ready（含原生初始化，单次小EPUB、开发机缓存），不推导P95或大书表现。一次后台启动PDF的requestAnimationFrame里程碑被延迟，保留原始13秒记录，不当成受控前台启动样本。实际原生触控/干净机器仍待验证。
