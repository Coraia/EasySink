# 触控板停手收尾优化

版本 `20261007-trackpad-release`，2026-10-07。

原来停手先等 240ms，再走至少 240ms、一直减速的动画；约半页处停手需要约 520ms 才落页，容易感觉纸张停顿。现在保持 240ms 无事件结束跟手，完成收尾用 110–180ms，回弹用 110–160ms。完成曲线从非零速度起步，前段加速、后段减速，到终点速度为零。约半页处的计划停手至落页缩为约 390ms，实际数字以报告中的浏览器测量为准。

240ms 同时作为输入流之间的边界：已经结算的流中，迟到惯性不会再抓下一张纸。跟手仍在每次输入更新后用相同时间基准启动计时器；回滑、慢速 1px 回滑累计、过半不提前提交、缩放和浮层隔离保持。Web 不提供统一手指离开事件，超过 240ms 的输入间隔会被当作停手，这是必须通过真实触控板体验校准的边界。

触控板模块只向 `release` 传递最后输入的处理完成时间；页面结算按原因选择触控板曲线，点击、键盘、纸边抓页使用原曲线。没有改变网格、反光、阴影、纹理分辨率或缓存限额。纹理等待的 release 时间不在 ready 回调时重置，迟到加载会被单独记入证据，不把等待掩盖成动画快。

`curlMetrics[].release` 提供最后输入至结算启动的 `idleMs`、`textureWaitMs`、`requestedDurationMs`、`actualDurationMs`、`inputToLandingMs`。无纸张场景沿用无 GPU 导航，不伪造指标。跟手的帧间隔包括停手等待，不能直接视为 GPU 掉帧。

[编码前失败清单](32-trackpad-release-failure-cases.md)。现有 E2E 增加双向停手的真实 native wheel 与 RAF/pin 轨迹、时间、单次提交和锚点校验。软件 GPU 测试先通过真实前后翻页预热，不替代真实 Mac 首次卷页验收。全量只在开发结束后运行，保留既有帧率门槛。

## 阈值试验与回退

初版尝试将停手判定缩短到 160ms。专项连续跟手两次丢失纸页，第二轮记录到 222.4ms 的实际 wheel 空档，明确不能以这组阈值宣布回滑不受影响；停止重试。恢复 240ms，保留加速收尾作为较小影响的方案。失败记录位于交付目录 `targeted` / `diagnostic`，没有删除。新的时间验收对应恢复后的真实产品阈值，未放宽既有 GPU 帧率检查。
