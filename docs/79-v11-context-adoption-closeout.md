2026-10-13。客户端 **1.1.0 build 9 已安装并完成原生定向验证**。用户此前真人接受 build8 的阅读、翻页、查词和触控板体验；本轮修复其指出的采用不更新原文、交互层级过深问题。build9 的新行为由代理验证，不伪称用户已再次验收。本文及候选清单记录构建验收时快照，当时尚未提交、推送或更改 GitHub Issue；后续提交状态以 Git 历史为准。

## 修复与边界

采用的语义见 [ADR-0008](adr/0008-contextual-reading-records.md)。旧版收藏确实已保存解释，问题是正文没有消费采用结果，并非用户理解错误。

- 精确语境出现的正文已有词注与词卡同步，词典和同词其他位置不变。
- 词卡直接预览并“用于此处释义”，无需先收藏；生成新解释仍不等于采用。
- 收藏详情替换词卡；阅读工具面板中的详情、出处与冲突核对内联显示，不新增第三层。ESC 先关闭当前内联区，保存失败时保留草稿。
- 兼容旧已采用收藏，无需重新生成或重新采用；取消收藏时原子保留独立采用及历史。
- 新采用保留并发 revision 条件写入；撤销保护后续修改。默认收藏备份承接采用及解释历史，不隐含导出掌握/保留偏好。
- 辅助密度0仍不强制显示词注；明确保留注释的现有规则不变。

## V2 入口

阅读主链路已经真人接受，不再将内核重写或全量重跑作为默认前置。下一阶段围绕“相近密度下帮助更准确而非注释更多”，进入最小评价协议与可撤回策略设计。

沿用 [V2验收问题](wayfinder/v1-v2/tickets/evaluation-gate.md)、[学习依据](wayfinder/v1-v2/tickets/learning-evidence.md)、[调整策略](wayfinder/v1-v2/tickets/adaptation.md)：

1. 先冻结需要帮助/不需要帮助/无法判断的判定方法，区分漏标、多标、释义错误和阅读打断；未见语境与开发样本分开。
2. 仅以明确反馈作为已知事实，查阅、收藏、采用和无操作不直接推断掌握；旧记录缺字段保持未知。
3. 最小候选先离线比较或只记录预测，不改变日常界面；确认收益后可选试用，随时撤回到build9基线。
4. 用户明确保留/隐藏优先，原文选区与翻页过程中不突然改变布局；不以逐页付费模型或增加注释密度换取表面召回率。

这些是进入V2的已有边界与建议顺序，不是已实现的V2，不替用户决定尚未对齐的跨语境泛化规则或编造F1门槛。
