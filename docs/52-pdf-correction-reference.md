## 拟议阅读交互

以原图印刷为 `modern theology`、识别正文错误显示为 `modem theology` 为例；这是构造示例，不是已经发现或复现的真实书籍错误。

1. 正常阅读不显示常驻纠错按钮，也不自动弹出校对任务。
2. 在 PDF 阅读版选中错误词或同一段内的小片段，沿用现有选区菜单，在“更多”中进入“修正识别”。原有翻译、语法、发音和笔记入口保留。
3. 选区附近的小卡片展示对应的原图裁剪及当前识别文字，只开放这段文字的编辑；不打开整页编辑器，不占用为译文预留的右侧区域。若来源区域无法可靠取得，应明确提示而不能展示另一个位置的图片。
4. 将 `modem` 改为 `modern`，通过“完成”或适合该输入框的快捷键应用，关闭卡片并返回同一阅读位置。Esc 取消，尚未应用的输入不能被当作已保存正文。完成动作本身提交修改，不增加授权或费用确认。
5. 以轻量状态反馈提示已修正并提供撤销；日常正文不遍布纠错标识。原图仍可通过已有来源入口核对，修正记录可按需查看。
6. 若出现整段乱码、串栏或错序，引导到 Q12 的重新处理与原版核对，不用一个文本框承担复杂版面修复。

这是一份备选能力的文字交互提案，不是已完成或已验收的可交互原型；Q20 已确定不自动纳入首期，后续是否引入需结合真实错误样本与原型另行决定。

## 拟议技术实现

只读核对发现当前 `src/wise_reader/content.py` 的块 ID 由类型与文字哈希生成（约第 90 行），`Anchor`（第 30 行）没有 PDF 原页/区域；`web/plugins/notes.js` 的 `resolved`（第 166 行）在原块/引文失配时可能改用第一个包含引文的块。这说明不能简单修改 DOM 或覆盖当前正文，就声称笔记、书签和续读仍能可靠对应。此处是静态设计风险，不是本轮复现的新故障。

建议把保留资料与阅读时生效的内容分开：

- 原 PDF、原页图像和原识别结果保持可回溯。
- 用户修正另存为本机的局部修正记录，包含来源文件/页/区域、基于的识别版本、原文字范围、前后文和替换文字。不靠阅读页码或改字后变化的哈希定位。
- 阅读时组合基础识别结果与适用的修正，得到供排版、查词、朗读和主动 AI 操作使用的当前文字；手动输入本身无需 LLM 请求。
- 应用或撤销修正需生成可追踪的内容修订，更新受影响的段落、分页与纹理资源，并迁移关联记录；不因一个词修正就立即重新转换或渲染整本书。具体失效范围与延迟仍须测量，不能承诺没有重排开销。
- 旧笔记原有引文保留，定位按来源及版本映射；范围重叠、引文重复或对应不确定时保留记录和来源位置，不能猜测绑定到另一处。
- 涉及变动文字的旧译文/语法/语境结果应标记为针对旧文字，不当作新文字的有效缓存；再次生成由用户主动操作，不因手动纠错自动外发或再次计费。不相关范围继续复用有效结果。
- 新一轮 OCR 不覆盖用户修正；可可靠映射时继续应用，映射不确定时保护修正及其原引用并标明状态，不把修正盲目应用到其他内容。

主要复杂度来自改字后的排版、来源与阅读记录的一致性，不是小输入框本身。端到端验收应覆盖修正/撤销、刷新与重启、分页边界、重复引文、已有笔记与书签、重识别冲突、翻页纹理及没有隐含付费请求；本轮未编写或运行测试。
