# V1.1 体验反馈修订 · build 3

2026-10-11。依据本轮五点反馈更新正式 Web、macOS 候选与阅读闭环原型。客户端已安装为 1.1.0 / build 3，正式 Web 版本为 `20261011-reading-feedback`；尚待用户体验确认。未提交或推送本轮改动。

## 行为

1. 语境解释直接点击“解释这里的意思”。移除范围选择、前后段勾选、字符数和截取计划；默认使用后台有界的当前句段。保留实际输入、缓存身份、结果未知不重发及重新解释预览后采用。历史解释不再额外展开请求上下文。
2. “已懂这里”恢复为“已掌握”。仅表达此处用法的理解，收藏与保留注释继续独立。
3. 选区完全包含于一条既有划线时（包含相等、部分单词与跨段锚点）显示“删除划线”，整体删除并可撤销。超出范围则显示“划线”，保存后合并并立刻切为删除。逐词查询仍占用原文点击，不抢占它来选择整条划线。
4. 阅读底部的“阅读样式”直接提供原文／轻／适中／多，调整即保存。“更多阅读功能”与阅读偏好也继续可用，明确保留的注释不因降密度被隐藏。
5. “需要加强的领域”用独立 `focus_domains` 保存。旧 `domains` 保留，不反转、不再抑制候选。只在合格且已有领域信息的候选中提升优先级，仍受辅助预算、开关和显式反馈约束；没有领域信息时不猜测，也不新增自动 AI。取消或清空恢复默认。

## 原因与修改位置

原划线菜单使用 `sameSelection`，只识别完全相等的选区；现在用同文档版本、同块字符范围的包含关系定位整条记录。菜单和删除操作使用同一判断，避免显示和实际动作不一致。实现位于 `web/source-selection.js` 与 `web/plugins/collections.js`。

语境交互位于 `web/assist-popup.js`、`web/collections-word.js` 与 `web/collections-dialogs.js`；密度入口复用 `web/reader-chrome.js` 原有控件和事件，不复制状态。领域由 profile/store/API/filter 与 `web/app.js` 连通，迁移缺省为空，自动保存失败可重试。原型同步更新 `web/prototypes/v11-reading-loop/`，正式业务仍使用真实阅读器。

## 走查与证据

本轮新增代码前已在 `outputs/v11-feedback-20261011/failure-plan.md` 记录失败方式。未写事后单元测试、未运行全套 E2E。主控直接使用浏览器／原生 UI，写入操作仅在隔离库完成，正式安装后验证实际页面与控件。

| 走查 | 观察 |
| --- | --- |
| 已有划线内用选区端点缩到部分原文 | 修复前为划线；修复后为删除划线 |
| 删除、撤销、扩大到整段再保存 | 整条删除可恢复；扩大后取并集并立即改菜单 |
| 已掌握及保留注释 | 可同时选中，收藏不自动选中 |
| 未配置 AI 时一键解释 | 直接打开阅读内配置，无上下文选择步骤 |
| 阅读样式切原文，再到更多切适中 | 即时生效，显式保留仍显示；偏好页同步 |
| 领域选两项、刷新、清空 | 自动保存并恢复，清空回默认 |
| 原型／正式 Web／已安装客户端 | 新入口实际可见；客户端续读锚点不变 |

主控 16 项定向走查详见 `outputs/v11-feedback-20261011/walkthrough.json`。领域协作验证另有临时库真实 HTTP 39 项、Chromium 12 项，候选数据为明确标注的本地回放，不能替代真实模型识别质量；证据包保存在 `outputs/v11-feedback-20261011/focus-domains-evidence.zip`，复现见 `docs/parallel/v11-focus-domains-status.md`。

保留的复验问题：未重启测试服务时，页面仍复用旧资源版本；重启后新资源版本通过。已有标记上的一次短距离原生拖选未产生范围，本轮通过“选择整段 → 拖动端点”复现子选区，不声称所有拖选方式均已验收。
