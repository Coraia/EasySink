## What to build

在所有纵向能力完成后，对真实 PDF 与已有阅读整体 review 和最终点击走查，给出可复现的通过/阻断结论，让用户验收后体验正式版本。

2026-10-08 执行更新：用户要求尽量并行、减少新增测试代码，以直接浏览器点击走查与性能记录验收；此约定更新父规格的自动化测试要求，转换依据、数据/费用约束及用户原型验收门槛保留。

## Acceptance criteria

- [ ] 逐项核对规格、领域术语和 ADR，确认本机/外部范围、版本/记录、资源、付费与资料生命周期实现符合决定，手动纠错仍是备选。
- [ ] 执行全部必需 PDF 场景与旧格式完整走查，最终以直接浏览器操作完成，不要求新增完整自动化套件；缺必要样本/真实设备不能通过 skip 宣称完成。
- [ ] 冻结主引擎、模型与完整依赖、真实材料/质量参考、浏览器/机器/设置、数值门槛与容差，后台负载配对指标及高清纸面守卫通过。
- [ ] 真实外部能力在实际采用范围验证；无真实凭据/兼容证据的能力明确未验证，不把模拟响应当真实计费或模型质量。
- [ ] 生成新的证据目录与源码/样本摘要、HTML/JSON、trace/截图、首失败、质量/来源标注、脱敏请求记录、原始指标及复现步骤，私有材料与凭据留本机。
- [ ] 用户对真实体验验收后才达到正式发布条件；任何必要门槛失败给出阻断项，不降低证据级别或静默放宽门槛。
- [ ] 保留本轮整体 review 的发现及修复/未修状态，验收结论与实际证据范围一致。
