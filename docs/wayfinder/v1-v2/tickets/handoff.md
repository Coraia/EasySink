## Question

基于已经确认的决策和原型，V1 收口、V1.1 与 V2 各自怎样进入规格与开发，哪些可以并行，哪些以真实验收为前置条件？

本票需明确：
- 各阶段最小可体验闭环、P0/P1 顺序与可独立移除的能力边界。
- 规格分界、技术接口与开发任务的交接依据；阶段可分别进入 to-spec，不把所有远期研究当成近期开发的阻塞。
- 对现有 PDF 验收与其他未完成工作的归属，明确决策票关闭、开发完成与用户验收三个不同状态。
- 每阶段真实走查的入口、性能与数据守卫、失败回退，以及用户体验反馈如何回到下一轮。
- 有证据后再给工作量和日期估计；仍在范围内的未知问题需展开成决策票后才能宣布整张地图完成。

收口依据：用户认可的阶段顺序、规格交接包与剩余未知清单。此票不执行开发、不自动发布规格/开发票，也不授予提交、部署或修改既有父票的权限。
