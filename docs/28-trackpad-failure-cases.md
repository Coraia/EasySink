# 触控板翻页：边界与失败用例（2026-10-07）

目标：正文中横向 wheel 手势翻动当前一页/跨页，复用现有纸张光影动画与源文锚点；一次连续手势只提交一次。纵向滚动不用于翻页。

编码前列出的失败路径：

- 少量抖动、纵向或斜向滚动被误认为翻页；方向反向；单页与双页步长错误。
- 每个 wheel 事件都提交翻页；动画结束后的惯性继续翻页；跨章节加载期间的惯性在新章节重复提交。
- 词卡、笔记、翻译、输入框、选中文本、展开工具层内的滚动穿透到正文；关闭面板后残余事件触发翻页。
- Ctrl/Meta 缩放被翻页劫持；浏览器横向历史手势或横向滚动抢走正文手势。
- wheel 的 pixel/line/page 单位造成阈值不同；系统自然滚动方向设置被错误反转。
- 页首/页尾、未完成分页、缩小窗口、关闭动画/减少动态效果、抓页中滚动导致重复或错误导航。
- 路由切换留下旧事件处理器、重复监听、定时器或旧 Reader 引用；翻页失败产生未处理 Promise。
- 新处理器造成持续计算、DOM 重排、渲染帧下降；已有按键、点击、抓页回归。

实现约定：按浏览器 deltaX 的正负决定下一页/上一页（系统设置决定手指方向）。累计 80 CSS 像素触发；轴锁要求横向幅度超过纵向 1.35 倍；连续事件间隔不超过 240ms 视为同一手势。该规则是基于 wheel 的启发式，Web 标准事件没有统一的触控板手势结束标志；真实 Mac 硬件仍需用户体验确认。

一个应用生命周期监听器动态读取当前 Reader，加载期间只吞掉正文横向惯性，不引用上一章节。模块可单独移除。没有轮询/计时器，不新增正文控件。

验收：真实 Chromium wheel 输入检验双向、阈值、轴锁、惯性跨动画/章节、面板/词卡/选区和布局；单独标记合成的单位/修饰键事件；最终运行完整浏览器 E2E 并保留 JSON、trace、截图和复现命令。生产页只验证交付加载，不修改用户阅读进度进行自动翻页。
