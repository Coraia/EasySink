# 正式版抓页翻书 · 开发与验收约束

先完成正式阅读器抓页翻书和光影，再进行第一期整体 review 与性能测试。

## 失败模式与验收

- 拖动方向反转、左页镜像错误；上中下抓取高度不同，纸边应随实际鼠标位移移动。
- 拖动或取消提前写入阅读位置；原文、页码、书签和笔记锚点应保持，完成后仅提交一次。
- 快速翻页、异步纹理未就绪、布局/密度变更、路由离开、Esc、窗口失焦或 GPU 丢失造成旧动画回写。
- 单页/双页/夜间背景失效、纸页内容方向错误、取消后正文空白、菜单或段落操作被复制到动画。
- 抓页区域覆盖文字、选择、语法、笔记、翻译、顶部 banner；工具层打开时不翻页，正文不隐藏。
- 章节边界、后台分页尚未完成时误判为书末；保留原章节导航，不跨过未就绪正文。
- WebGL 不可用、纹理超时、减少动态效果、关闭动画应保持可用的翻页及取消。
- 光影应体现折线方向和弯曲程度，平面原文保持对比度，支持关闭光影。
- 每次移动只改 uniform；每个阅读器一个 WebGL 上下文；纹理上限 6 页/1600 万像素；离开释放。

## 验证顺序

实现后进行定向浏览器 E2E（真实鼠标按住/移动/松开），保留首次失败、截图、JSON 和重现步骤。性能测量与逐帧截图分开。整体性能和代码 review 在该功能完成之后进行；不运行单元测试、不在开发中运行全量 E2E。
