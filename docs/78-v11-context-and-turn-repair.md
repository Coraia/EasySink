## 翻页：机制与证据边界

去掉同一刷新周期的重复首帧提交；相邻 PDF 来源仍提前解析，但仅在真正跨来源的边界屏抓取两面纹理，避免挤掉当前屏的六叶缓存。偶数末屏不再预热虚构空白；奇数尾页的真实补齐空白保留。相邻范围和本范围预热均复核页位置/代次，换屏后停止继续旧批次。在途单次捕获仍可能完成，不声称全部撤销。

原生 WebKit 调用栈将一部分等待定位到显示缓冲准备；增加每个尺寸/布局最多四帧的空闲透明预热。开始翻页、换书、改排版或释放阅读器时撤销。未降低 DPI、纸张几何、光影或动画时长，缓存仍为六叶/96MB，没有持续后台动画。

候选 E 的两组原生会话共47个去重场景：39次点击翻页全程 P95 均≤31ms，包含单/双页、前后交替和 PDF 来源切换；7次取消的松手后 P95≤28ms，另有1次完整拖动。全部来自本机 WKWebView 的实际键盘/鼠标操作，并非物理触控板签收。

**保留不利证据：**47条 legacy 全程间隔有3条取消 P95 超34ms；不能说47条全过。按输入驱动的页面停留期间并不持续绘制，旧指标把输入间隙混入帧间隔；新诊断增加有界输入事件及 releaseActive，后者从 release handler 开始，包含到首帧的等待和所有后续间隔。截断或无样本标为 incomplete，不能以0ms通过。旧指标完整保留。点击过程仍有孤立98ms（空闲后的首次）及158ms（早期工具观察未隔离）间隔，不宣称零长帧；独立复核没有允许删除这些点。计量是 JS 提交间隔，不是屏幕呈现或物理输入延迟。

证据：`performance/candidate-e-all-scenarios.csv`、`candidate-e-aggregate.json`、各 `*-native.json`、`review.md` 与 `review-final.md`。D候选P95达到36ms且最大119ms，已回退；没有挑该候选中的好轮次充数。
