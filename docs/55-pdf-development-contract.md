# PDF 一期：开发契约

日期：2026-10-08。配套 [规格](54-pdf-spec.md) 与已确认的 [产品决定](53-pdf-shared-understanding.md)。本文件描述拟实施的 Interface 和不变量，不是已编码、已安装或已验收的报告；具体引擎、模型和版本仍需选型。

## 1. 接入方式

建立一个深的 PDF 内容处理 Module，让书架和阅读器调用少量业务操作：导入、读取表示、查询任务、执行明确的处理/资料操作。转换 Adapter、来源转换、检查点、结果复用与费用尝试记录属于其 Implementation；不让每个 UI 插件分别处理 Docling/MinerU/PaddleOCR 输出。

旧格式走已有导入通路和响应 Contract。PDF 采用独立异步通路，在短事务内形成原件、书籍归属与任务登记，转换在独立 worker 进程执行；不把重计算搬进现有用户库事务或旧文本 AI 队列。

既有阅读器继续使用结构化篇章和原文锚点。PDF 新增来源对象与版本映射，避免为了适配新格式要求所有旧书重导、重新分配 ID 或一次性重建所有记录。原版使用独立来源查看 Adapter；阅读版继续走原有阅读及翻页 Interface。

## 2. Module 的职责

| Module | 职责 | 调用方不应了解的 Implementation |
|---|---|---|
| PDF 内容处理 | 接收原件，统一处理操作、版本、来源、任务与资料生命周期 | 不同引擎输出、模型准备、页/区域拆分、检查点存储细节 |
| 既有书架与阅读记录 | 统一书籍归属，记录原文与原图笔记、书签及续读 | OCR 错误判断、供应商调用、不同坐标系 |
| 阅读表示 | 按需取得可读范围、有效文字、结构内容和资源 | 原件存放方式、整书重新序列化、模型缓存 |
| 来源查看 | 显示 PDF 原页，缩放/定位所选区域，返回原锚点 | 引擎 bbox 原点、旋转坐标差异 |
| 既有分页及页绘制 | 对一致的表示分页，生成静态与翻页资源 | 外部识别等待、费用重试、整书任务状态 |

Module 名称用于描述职责，不要求一个职责创建一套新微服务。只有确实变化的转换、来源查看和外部供应商在内部 seam 使用 Adapter；测试从已有浏览器业务入口穿过同一外部 Interface。

## 3. 逻辑资料模型

以下是存储 Contract，不限定物理表名或文件组织。

| 对象 | 必需信息 | 不变量 |
|---|---|---|
| 原件资料 | 原件身份/内容摘要、字节数、格式、元数据、PDF 原页数量与标签、可访问状态 | 身份按实际文件内容；原页序号与印刷页码标签分别记录；原件不被重识别覆盖 |
| 书籍归属 | 既有书籍身份、原件关联、回收状态、当前表示、原版/阅读版可用范围 | 一个完全相同的原件只有一个活动归属；书籍可在章节尚未形成时出现在书架 |
| 来源对象 | 稳定对象身份、原件、原页/区域、有序位置、可用文字对应 | 不仅由可见文字哈希生成；来源坐标不随字号和窗口变化 |
| 转换版本 | 版本身份、引擎/模型/设置摘要、来源范围、结构内容、有序映射、质量及产物关联 | 不可变；局部替换不能覆盖未处理范围；新旧结果可回溯 |
| 范围就绪状态 | 范围身份、待处理/有效/原图回退/拒绝、检查依据与问题类别 | 处理完成不等于文字可靠；回退不是结构识别成功 |
| 保留产物 | 原件/裁剪图、有效结果、付费响应与必要中间产物、摘要、格式、引用关系 | 普通缓存清理和默认到期不删除；同一资料可被多个版本或记录引用 |
| 阅读锚点扩展 | 原有引文及上下文、表示版本、来源对象、区域/文字范围、映射状态 | 已存引文不静默改写；歧义保留旧引用与来源，不能凭首个文字匹配猜测 |
| 转换任务 | 身份、业务意图、目标范围、方式、配置快照/凭据引用、执行状态、检查点、限制原因、代次 | 浏览器关闭不影响任务；取消任务不在重启自动续跑；快照不含输出到 UI 的明文凭据 |
| 付费尝试 | 操作与尝试身份、范围/配置摘要、预留、派发意图、发送确定性、供应商结果引用、响应摘要、用量及费用类别 | 相同业务意图不能重复派发；可能已发且结果未知不自动重试；供应商结果引用不是保证退款 |
| 资料清理操作 | 操作身份、选定类别/书籍范围、开始/完成/失败、已释放/仍保留范围 | 清理语义可核对；不能把释放临时缓存实现为删除整本书 |

原件、保留产物和数据库采用可恢复的提交顺序。成功接收状态仅在原件登记、书架条目和任务登记可恢复后返回；崩溃恢复需识别未完成登记和未引用临时产物，不能生成假成功或重复书籍。

## 4. 外部 HTTP Contract 草案

路由名称可在实现前统一，但下列输入、返回和失败语义必须保持。所有接口沿用现有本机访问控制；客户端不能通过任意路径、书籍身份或区域访问未导入资料。

| 方法与资源 | 输入/范围 | 返回与行为 |
|---|---|---|
| POST /api/pdf/imports | 文件上传、显示元数据、导入意图身份 | 新导入返回 202 和书籍/任务身份、复用标识、可用状态；已有原件复用返回原归属，不新发任务或付费调用 |
| GET /api/pdf/books/{book_id} | 书籍身份 | 原件摘要、原页标签、当前版本、可读范围及处理状态，不返回全书正文 |
| GET /api/pdf/books/{book_id}/ranges | 来源锚点或有界范围 | 当前表示版本、所需结构内容、来源及局部资源引用，明确范围缺口与下一范围 |
| GET /api/pdf/books/{book_id}/source | 原页/区域、显示尺度 | 有界的原页读取或资源定位，支持查看器所需的分段读取；坐标与版本可核对 |
| POST /api/pdf/books/{book_id}/operations | 原页/区域、业务操作、配置选择、意图身份、预期代次 | 本机重新识别、外部增强、本地重放或重新生成分别解释；返回复用结果或任务，不执行含糊的“自动智能处理” |
| GET /api/pdf/tasks/{task_id} | 任务身份 | 执行状态、范围就绪、限制原因、调用/用量/费用类别；不暴露凭据 |
| POST /api/pdf/tasks/{task_id}/operations | 暂停/继续/取消/明确的新尝试、意图身份、预期代次 | 合法状态转换及当前状态；相同操作重复送达仍只有一次效果，过时代次返回冲突 |
| POST /api/pdf/books/{book_id}/lifecycle | 回收/恢复、业务意图 | 回收停止后续处理；恢复已有资料、未完成本机任务保持暂停 |
| POST /api/pdf/materials/cleanup | 明确资料类别与书籍范围、业务意图 | 显示释放及保留范围；不能把一般清缓存变成删除记录或付费响应 |
| GET/PUT /api/pdf/settings | 可选次数限制、转换相关设置 | 明确默认限额未开启、启用后的计数含义；不改变旧阅读 AI 的限额或设置 |

错误分类至少区分格式不可读、密码/访问受限、模型未就绪、空间不足、能力不兼容、已回收、代次冲突、资料不足、范围质量问题及结果未知。等待模型/空间/限额与原件损坏不同；返回可操作的状态和原因，不把所有异常都包装成“文件损坏”。

PDF 上传字节/页数上限独立于现有旧格式上限，按样本和资源验证配置。先校验容量并采用有界上传，不能全书多次拷贝到内存；原版、范围与资源读取也必须有界。具体限额在实验前冻结，不凭上游默认值当作本机可用上限。

## 5. 任务和范围的状态

任务状态、范围就绪、阅读视图和付费尝试分开记录，不能用一个进度数字代表全部。

| 情况 | 系统行为 | 读者看到的结果 |
|---|---|---|
| 原件已登记、模型尚未准备 | 保留书架条目与原件；独立记录模型准备，原版可用后开放 | 原版可核对，阅读版等待模型；模型下载不描述为文档外发 |
| 页/区域完成并检查通过 | 保存检查点与完整结果，再发布该范围 | 可读范围增加，未处理部分仍显示处理中 |
| 仅部分范围成功 | 保留合格范围，分别记录回退/拒绝/剩余范围 | 允许读合格内容，不能显示“全书文字就绪” |
| 用户暂停/资源节流/限额暂停 | 停止后续工作，原因分别记录；保存已完成内容 | 明确暂停原因与可继续条件 |
| 用户取消 | 停止派发后续工作；保存已有资料和在途尝试状态 | 已完成内容可用，不因服务重启继续旧任务 |
| 服务重启 | 恢复允许执行的本机检查点；可能已发外部尝试不重派 | 原进度和范围恢复，未知结果仍未知 |
| 切书/关闭浏览器 | 页面订阅结束，任务不取消；阅读视图不接受旧路由迟到更新 | 书籍处理继续，当前新书不被旧结果替换 |
| 回收书籍 | 增加生命周期代次、停止后续工作，隔离迟到发布 | 书籍移出活动书架，仍可恢复 |
| 恢复书籍 | 原件/记录/有效结果恢复；未完成本机任务暂停 | 可继续读已有内容，继续处理为明确动作 |

原页是任务工作单元的常用来源，但转换 Adapter 是否支持有界页/区域与渐进结果必须实测。不能先整书识别完成、再逐页显示完成标记，冒充真正的首范围提前可读。

## 6. 来源、版本与图像交互

采用统一来源坐标约定并保留原页旋转、裁剪及标签信息；Adapter 输出时完成原点转换，查看器按相同变换定位。文字、图片、表格、公式对象可以对应一个或多个原页区域，跨页内容保持顺序和完整区域集合。

阅读版跳原版时保存原文锚点、视图、当前可见对象及阅读偏好，原版关闭后恢复原位置；不按已经变化的阅读页码恢复。原图回退在原位置呈现，只裁取必要的完整公式/表格区域；复杂结构无法可靠裁取时明确来源与问题，不展示错页图片。

新转换版本先做范围与记录映射。当前页的翻页、选区、笔记编辑和理解辅助操作持有稳定表示；等待安全时机切换并保留锚点，未显示范围可提前更新。依赖旧文字的译文/语法解释不能当新文字结果复用；缺失映射不自动重发 AI，保留旧引用与来源并标明状态。

图像笔记在阅读版对象上操作，保留图像及原页定位；标识、新增、编辑、删除撤销、入口列表及跳回遵循现有笔记体验。原版仅选择处理范围，不复制完整笔记工具；图像对象没有可靠文字时不伪造文字选区。

## 7. 复用、重放和付费尝试

结果复用身份至少覆盖原件内容、精确处理范围/必要上下文、输入表示、引擎/模型、提示及处理版本、选定服务配置。成功通过结构/来源检查的结果才可复用，失败或未知不算有效缓存。

保留响应和必要中间产物作为重放资料。重放只做本地整理和构建，缺材料或版本不兼容时显示不可重放；不能悄悄执行新付费调用。当前普通结果缓存不能直接替代这一契约，需保存可重放的资料及来源。

派发流程：先查有效结果 → 原子登记/复用业务意图并预留限额 → 写持久派发意图 → 发请求 → 记录响应和用量 → 验证 → 在任务/书籍仍可发布时提交结果。崩溃点必须可识别，结果文件与记录之间也需恢复；已经收下响应却提交失败应本地恢复，不能重新收费获取。

存在派发意图但不能证明未发时，按可能已发处理并保留限额占用，次数确定性也如实显示；只有确定未发可以释放。结果查询不等于新识别请求；如果服务查询本身可能计费，能力与费用必须验证，不能套用“本地重放”名称。

次数上限约束应用新派发的付费/费用未知外部请求，按预留与未知占用处理并发；不能保证供应商内部调用或实际账单恰好等于应用次数。费用类别为可靠已知、估算或未知，显示币种、依据与用量；没有价格不能显示零费用。用户操作已授权，无新增费用确认屏。

## 8. 阅读性能和资源

按范围取内容，首页与近邻优先；重开已转换书籍不重新 OCR，不从全书内容开始整本分析。分页和翻页只准备当前表示及有界近邻资源，任务发布不能让所有段落、所有注释或全部纸面重新生成。

worker 默认有界并发；阅读活跃或测量超出守卫时暂停新的推理单元，必要时结束/卸载可恢复的本机 worker，不能假定一个后台线程或降低 nice 值就能避免 MPS 与浏览器 GPU 竞争。不可中断的大步骤、模型驻留和换页压力作为候选选型条件，记录首次失败。

新图像/公式采用可被静态 DOM 与纹理生成共同消费的本机有界资源。原版 Canvas 不直接塞入正文纹理；资源嵌入、字体、SVG 引用和已加载状态必须明确。按当前 DPI 准备，不能通过把硬件纹理降成软件低分辨率来掩盖转换负载。

原有 34 ms 的特定翻页/输入 P95 守卫、24M 纹理缓存像素预算、6 张缓存守卫和 DPR 1/2/3 路径以既有场景为准，新增内容不可放宽。真实本机无转换与后台转换的配对指标另按 [验收计划](56-pdf-acceptance-plan.md) 冻结和比较；浏览器内部计时不冒充物理指尖延迟。

## 9. 资料管理与增量接入

保留资料和临时阅读缓存有不同生命周期。正常缓存释放不删除原件、阅读记录、有效版本或付费响应，关闭插件也不删除这些资料；重要资料默认不按天到期。清理按明确类别和范围执行，结果可核对；删除引用关系不得提前释放仍被其他版本/笔记使用的产物。

磁盘压力预留上传、转换产物和响应提交空间，先释放可本机重建的临时资源，仍不足暂停新工作。正在写入的临时内容不标成功，故障后可恢复或明确失败。永久清理与回收不同，恢复保持原归属和记录，未完成任务暂停。

书架/篇章/锚点的数据扩展遵循“先增加新信息，旧通路继续可用，再接入 PDF 调用方”的顺序；本规格不要求广泛重命名或整库重建。实现阶段若发现必须广泛重构，先给出可逐批保持回归通过的 expand–contract 顺序，再在 to-tickets 依赖中表达，不把数据库、后端、前端分别拆成不可验收的水平任务。

## 10. 待验证事实与开发前置条件

- 固定候选引擎/模型/全部依赖版本及许可，验证本机运行路径、来源坐标、逐步结果、可停止性和资源上限。
- 为实际材料建立独立参考与类别指标，并冻结新增 PDF 的质量/耗时/资源门槛；不是要求用户猜参数。
- 通过相同高层导入/阅读路径比较候选，证明至少一套满足质量和不干扰旧阅读的门槛；未满足不进入正式开发。
- 固定用户确认的交互原型后实施；手动纠错保持备选，不顺便实现整书翻译或原版全套学习工具。
- 当前仅交付契约，用户已确认浏览器 E2E 主验收 seam，tracker 已配置为 Coraia/EasySink GitHub Issues；规格发布后展示纵向 tickets，按批准依赖推进。
