# PDF 阅读版、正文覆盖与手势状态修复

2026-10-08。用户要求继续优化，并报告“已可读但像是原版”和“触控板未就绪”。本轮不重置上轮 OCR 实验预算、不增加引擎/下载/付费调用；复用已保存真实 OCR 结果改进布局，最终重跑真实整书验证仍需满足 180 秒。

## 目标与反馈

- 当前 `#/read/67` 应保持可选、可重排的阅读版；来源页码不能让人误以为已切到原版。真实原版应只通过含义清楚的核对操作打开，并可返回原位置。
- 书架/导入/处理详情不能把含图片的 566 页全部称为完整可选正文。保留图像内容与 OCR 正文分别说明，状态来自真实处理结果。
- 在已知简单多栏/侧栏页上从已有 OCR 框恢复阅读顺序；复杂表格、公式及不确定部分继续保留原图。不能仅为降低回退数量而输出错序或重复正文。
- 触控板服务运行、浏览器接入、原生事件到达、真实手感是四个独立信号；不能把启动成功改名为手势可用。

## 改动前失败方式与基线

浏览器实际读取 `#/read/67`：无 PDF 原版核对窗口，11 个文字段落、0 张图，显示“中文版序”；标题中“原页 9–16”是来源范围。正式任务完成 566 页，其中 278 页含原图，20 页没有发布可选文字；旧书架仍称“阅读版已就绪 / 566 页可读”。

实际 `python3 scripts/trackpad_lab/manage.py status`：`ok=true, native_events=0, clients=0, active_clients=0`。这一结果不能解释为浏览器已连接。

改动前记录可能失败方式：旧缓存掩盖变更；图片被当成文字覆盖；空白页被误判失败；多栏被逐行交错、边栏混入正文、跨栏标题重复、表格被误当普通段落；安全静默更新丢失位置/笔记；手势服务权限不足或 helper 退出但端口仍活；WS 路由/来源/客户端令牌不匹配；重启后没有重连；模拟事件冒充真实设备验收。

按约定只做真实浏览器/API/已有原始结果重放，不新增单元测试，不在开发中运行完整 E2E 套件；截图、原始失败与输出保留在 `outputs/pdf-reading-clarity-20261008/`。主控独占浏览器、正式资料更新与 UI；并行会话独占手势接入和布局适配，写集不重叠。

## 已复现的续读缺陷与修复

独立书库 18886 使用同一本真实 566 页 PDF。将旧 Docling 产物第 1 页的真实图片区域作为阅读位置，通过已有进度 API 保存，然后在浏览器点击首页“继续阅读”：旧版会自动弹出 PDF 原版窗口（`stale-resume-before.json`）。并非用户主动核对。

原因：续读位置与显式旧引用共用 jump 逻辑，图片区域在新版 OCR 不匹配时被当作主动查看历史引用。修复后，续读带临时 resume intent；自动恢复优先回到同一源文件的同一原页，不伪造精确引用匹配，也不自动弹原版。若源页不可用，回到原比例。显式笔记/书签仍保持原版核对。原版返回使用自动恢复，避免旧位置再次弹窗。

浏览器同一路径复测：`stale-resume-after.json` 中 ready=true、originalOpen=false。先一次仅 hash 导航仍用旧模块的结果单独保留为 `stale-resume-old-loaded-module.json`，之后实际 reload 获取新资源；不删除失败。对照操作：同一个旧图片区域保存为隔离书库书签，点击“跳到原文”仍会打开原版第 1 页；返回阅读版成功（`historical-bookmark.json`、`source-return.json`）。没有改动正式用户的书签/笔记。
