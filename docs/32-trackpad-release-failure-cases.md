# 触控板停手收尾：编码前失败清单

目标：纸页随手势保持可逆，停手后更快进入连续收尾，先加速再轻落页。仅改触控板结算，不改变点击、键盘和纸边抓页曲线，不降低光影或纹理品质。

- 停手识别过迟，纸页悬停后才继续：无输入阈值从 240ms 调到 160ms；原有 240ms 流边界保留，避免尾部惯性再抓下一张纸。
- 收尾时间过长或一直减速：完成用 110–180ms 加速再减速的曲线；撤回用 110–160ms 回弹。
- 连续输入或慢回滑被提前提交：实际 native wheel 连续输入期间原文/锚点不变，回滑仍取消。Web 不提供统一触控板手指离开事件，超过 160ms 的真实空档视为停手；真实 Mac 验收需明确这个边界。
- 惯性/连发造成重复翻页：同一 240ms 流中只结算一次；缩放、浮层、选区不受影响。
- 曲线换段跳跃、方向反转、落页闪回：记录真实 RAF 进度、pin、结算时间和结果；左右方向与原锚点检查。
- 纸页纹理尚未准备导致假快或异常：记录纹理等待、真正开始与结束时间；不将软件 GPU 预热测试当成冷启动或实际 Mac 帧率证明。
- 取消、重排、路由离开后迟到提交：原有清理与中断 E2E 保留。
- 单纯缩短动画掩盖 GPU 掉帧：独立运行已有 12 次抓页帧率检查，不调整门槛；失败如实保留。

使用现有独立测试服务和 E2E，不写单元测试。专项最多两次无进展即停止并保留证据；全量只在开发完成后运行一次。最终产物记录当前代码、时序、首轮失败、复现命令和人工验收边界。

## 开发中观察与方案收敛

160ms 方案连续两次失败；第二轮真实输入出现 222.4ms 间隔，预览提前回弹，停止继续重试该方案。回退到原 240ms 结束判定，只优化自动收尾。这个回退降低慢手势误判风险；计划半页停手至落页约 390ms，真实时长由 E2E 单独记录。
