## 修复前列出的失败方式

连续阅读：边界闪加载页；后退落到上一范围旧进度而非末页；鼠标能翻但手势到边界失效；拖回取消却更新来源；慢请求提前移除原页；失败后锁住；提前加载整书拖慢打开；来源切换后笔记/书签误绑旧文档；排版变化使用陈旧缓存。

导入就绪：仅安装可用但 GPU 不足；状态检查后模型切换造成过期；检查超时长时间阻塞导入界面；远端不可用误禁用本机或 EPUB；状态检查隐式加载模型/推理；UI 拦截但直接 API 绕过；排队后状态变化；原件已经保存但报错使其无法恢复；服务恢复后仍沿用失败缓存。

## 验收路径

- 真实 PDF 跨范围前进/后退：纸面动画可观察、正文无“正在打开”、来源与落页一致；同范围翻页不退步。
- 撤回/取消不改变来源；源范围缺口不伪造连续内容；网络失败保留当前页，可再次尝试。
- 导入框可明确查看当前电脑与 Omarchy 状态和检查时间，刷新后更新；不能把仅连接成功写成 OCR 成功。
- 明确不可用状态阻止选择该服务/启动该处理，其他格式及可用处理路径保持可用；提交与实际启动再次检查。
- 服务失效使用受控故障注入覆盖，不停止用户模型。真实就绪探测与模拟失效证据分开记录。
- 最终回看正式入口、浏览器错误、可复现步骤及截图。真实硬件手势验收不由模拟输入替代。

## 已完成的实现

- 相邻 PDF 范围在接近边界时有界预备，沿用当前纸张渲染器与手势过程。翻页完成后同步接入预分页内容，再挂载新范围的工具，不经过路由加载占位。反向进入上一范围末屏；取消和请求失败保留当前范围。纹理缓存按文档身份隔离，复用同一个 GPU 上下文。
- 导入框分别显示本机与 Omarchy 当前状态、检查时间和刷新入口。空闲且可见时定期刷新；选择文件后重新核验。远端不可用不隐式改选位置，也不禁用 EPUB/TXT/Markdown。
- Omarchy 使用独立 RapidOCR/medium 程序，`ocr67` 是另一个 GLM-OCR 服务。现在轻量检查固定模型/配置、GPU 驱动/空闲显存与实际 llm-switch 冲突服务（含启动中）。不启动推理、不切模型、不发文档。队列获得执行权后还会重新检查，不满足时暂停，原件和已完成内容保留。
